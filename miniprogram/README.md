# 智能日程管家 · 微信小程序版

深圳大学 物光创新实验室 2026 招新项目 —— 小程序（微信云开发）版。

> **两个名字，指的是两样东西**：小程序在**微信里的名称**是「**青年时间管理助手**」
> （用户扫码后看到的就是它），而**本项目**叫「**智能日程管家**」（招新提交的项目名）。
> 界面里露给用户看的名称已统一成前者；代码注释与文档保留后者。

这是同一个项目的第二个前端：Python/Streamlit 版面向电脑浏览器，这一版面向手机。两版**共用同一套业务规则**（节次作息、周次与单双周、缺口分析、任务模型），云函数侧重写了 Python 的纯逻辑部分，并用 node 单测与 Python 版逐条对照。

## 一、这个版本有什么

| 页面 | 能做什么 |
|---|---|
| **课表**（周视图） | 按周次显示课程网格，自动标出「午休」时段；单双周课只在对应周出现。落不进任何一节的条**集中在表头下第一行的「其他时段」**；三种类型（日程 / 截止 / 子任务）角标不同、页脚有图例 |
| **任务** | DDL / 日程 / 子任务列表，三种状态（待办 · 已完成 · 已结课） |
| **添加 / 编辑** | 手动录入；任务类型、优先级、重复（每周 / 单双周）、节次、时长。**时间一填好就提示该时间段是否已被占用**，并可一键「换到最近的空闲课节」（只提醒，不阻断保存） |
| **AI 录入** | 说人话就能加日程（「下周三下午三点开组会」），也能把一个大任务**拆解**成子任务。入口在**任务页**：顶部「AI 录入」按钮，或在某条任务上点「拆解」直接跳过去 |
| **我的 / 导入** | 学期开始日期、作息表查看（标出哪些节次是导入时**校准**的）、**导入 .ics 课表**、**拍照识别课表**、**到期提醒的开关与授权入口**、导出备份、关于 |

「已结课」不是手动勾的：每周重复的课，上完**最后一次课**之后自动算结课，不用你去删。这与 Python 版 `task_manager.py` 的判定完全一致。

**缺口分析**：把待办任务的总耗时和一周的真实空闲时间对比，告诉你这周排不排得下、缺口多少分钟（`utils/planner.js`，从 Python 版 `planner.py` 移植）。

## 二、跑起来要几步（都得你本人操作）

> 下面这几步依赖你的微信账号与云环境，**别人无法代做**，我也无法替你验证。每一步都写清了"做完应该看到什么"，照着对。

### 第 1 步：注册小程序，拿到 AppID

1. 到 <https://mp.weixin.qq.com> 注册**小程序**账号（个人主体即可，免费）。
2. 后台左侧「开发管理 → 开发设置」里找到 **AppID**（以 `wx` 开头的一串字符）。
3. 把 AppID 填进两个地方：
   - `project.config.json` 的 `"appid"`（仓库里是占位符 `YOUR-APPID`，填上你自己的即可）
   - 用微信开发者工具打开本项目时，工具也会问一次

### 第 2 步：开通云开发，拿到环境 ID

1. 用**微信开发者工具**打开本项目目录（工具下载：<https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>）。
2. 点工具栏的「**云开发**」按钮 → 按引导开通（选按量付费的免费额度即可，个人项目够用）。
3. 开通后会看到一个**环境 ID**，形如 `cloud1-9gxxxxxxxxxxxx`。
4. 把它填进 `app.js` 顶部的 `ENV_ID`（现在还是占位符 `YOUR-ENV-ID`）。

> `app.js` 里做了保护：**只要 `ENV_ID` 还是占位符，就跳过初始化并在控制台给出中文警告**，而不是拿一个假环境去初始化（那样只会抛出一串看不懂的错）。所以如果你看到「云开发未初始化，请检查 app.js 里的云环境 ID」，就是这一步没做。

### 第 3 步：建数据库集合

云开发控制台 → 「数据库」→ 新建**三**个集合（名字区分大小写，不要写成 `Tasks`）：

| 集合名 | 权限设置（**很重要**） | 索引建议 |
|---|---|---|
| `tasks` | **仅创建者可读写** | `_openid`；`_openid+date`；`_openid+done` |
| `settings` | **仅创建者可读写** | `_openid`（唯一） |
| `reminders` | **仅创建者可读写** | `_openid` |

`reminders` 是 DDL 到期提醒用来记账的（「这条截止已经提醒过了」＋「这次下发为什么失败」）。
**不建它的表现**是 `remind` 报 `collection not exists`；不用 `remind` 的话可以先不建。

**千万不要选「所有用户可读」** —— 那会让别人的日程对你可见。「仅创建者可读写」配合云函数里的 `_openid` 过滤，才是"每人只看得到自己的数据"。

索引建议、字段结构、为什么要这样设权限，见 `docs/数据库与索引.md`。

### 第 4 步：上传部署 4 个云函数

在开发者工具左侧文件树里，对 `cloudfunctions/` 下的**每一个**目录分别右键 → 「**上传并部署：云端安装依赖**」：

- `tasks` —— 增删改查、统计、设置、批量导入
- `aiParse` —— 自然语言 → 结构化日程，**以及课表截图识别**
- `aiDecompose` —— 大任务 → 子任务
- `remind` —— DDL 到期提醒（每 5 分钟定时扫描 + 微信订阅消息）

> `tasks` / `aiParse` / `aiDecompose` 三个是主体功能，都要传。只传 `tasks` 的话课表和任务能看，但 AI 功能会提示不可用。
> `remind` 是**可选**的：不部署它，其余功能完全不受影响。
> 它要多做三步后台配置（订阅消息模板 ID + 环境变量 + **确认定时触发器**），见 `docs/到期提醒.md`。

### 第 5 步：配置 AI Key（可选，但不配就没有 AI 功能）

AI 用的是**智谱 GLM 的免费档**（`glm-4.7-flash`，输入输出都不收费）：

1. 到 <https://open.bigmodel.cn> 注册 → 「API Keys」页新建一个 Key。
2. 云开发控制台 → 「云函数」→ 选中 `aiParse` → 「配置」→ **环境变量** → 新增：
   - 变量名 `ZHIPU_API_KEY`，值填你的 Key
3. **对 `aiDecompose` 重复一遍**（两个函数各配一次，环境变量不共享）。

不想用智谱也可以：把变量名换成 `DEEPSEEK_API_KEY`、值填 DeepSeek 的 Key 即可，代码会自动识别，不用改任何代码。两家都配了的话，用哪个由 `LLM_PROVIDER` 决定（不填就是智谱）。

> **Key 只放在云函数的环境变量里。** 不要写进小程序代码 —— 小程序代码是可以被反编译看到的，写进去等于公开。后端也是这么设计的：四个云函数都**只从 `getWXContext()` 取身份**，前端就算伪造 `openid` 字段也会被剥掉。
>
> 没配 Key 时，AI 功能会返回一句统一的「AI 服务暂不可用」，手动录入、课表导入、周视图全都照常用。
>
> 也可以让用户**自填**自己的 Key（「我的 → AI 设置」），优先级高于预置 Key，
> **用谁的就消耗谁的额度**，不会烧机主的。详见 `docs/部署云函数.md` 第 2 节。

### 第 6 步：自己先看，再给同学看

- **自己预览**：开发者工具里直接就能看，模拟器或点「预览」扫码用手机看。
- **给同学用**：后台「成员管理 → 体验成员」加上对方的微信号；然后在开发者工具点「**上传**」提交一个版本，再到后台「版本管理」把它设为**体验版**，同学用微信扫体验版二维码即可。

## 四之二、四个问题的定位与修复

### 1. 用真实数据反推根因

2026-10 的真机反馈带来两个现象：**① 课程时间与导入文件里的不符**；**② 子任务与截止不能在时间表里显示**。
看起来是两件事，其实是**同一个根因**。

**定位方法：不猜，拿真实数据反推。** 我用同一份真实数据，把课表页真正在用的定位函数跑了两遍 ——
一遍喂**内置默认作息**，一遍喂**导入课表时校准出的作息** —— **3 条任务里有 3 条结论不同**：

| 条目 | 内置默认作息 | 导入时校准出的作息 |
|---|---|---|
| 截止「提交材料」`end_time=12:00` | 12:00 落在 11:40–14:00 的午休空档里，**任何一节都落不进去** → 掉进「其他时段」 | 落**第 5 节**（11:45–12:25） |
| 子任务「写实验报告」16:00–17:00 | 第 **7** 节 | 第 **9** 节（16:00–16:40） |
| 子任务「找家教」08:00–12:00 | 第 **1** 节 | 第 **5** 节 |

**根因**：导入课表时其实**算出了**校准作息（`utils/ics.js` 的 `parseIcs` 会返回 `periodTimes`），
但导入流程**只取了 events 与 warnings，从来没把它写回 `settings`**。
于是课表页一直拿内置默认作息去算"这个时间属于第几节"——
**文件里写的时间是对的，屏幕上的行号是错的。**

**修法**：

- 两条导入路径（**替换** / **追加**）成功之后都持久化 `period_times`；
- 合并语义是**"新节次覆盖同名、未涉及的保留"**，不是整体覆盖 ——
  否则一次只校准了几节课的导入会把其它节次的作息抹掉；
- **导入成功与作息保存解耦**：作息没存上**不会**把导入说成失败，
  只在页面上多一行「作息校准未保存（课程已导入）」；
- **可见性**：定位不到的条目原来落在表格**最末尾**的「其他时段」行，真机上要滑到底才看得见 →
  移到**表头正下方第一行**；并给三种类型加了可区分的**角标**（「程 / 止 / 务」）与页脚**图例**。

### 2. 一类反复出现的系统性 bug：排版与统计各算一套

同一件事，**画图的那套逻辑**和**算数的那套逻辑**各算各的 —— 在本项目累计出现过**四次**：

| # | 表现 | 后果 |
|---|---|---|
| ① | 「空闲 N 节」按**卡片数**算，而不是按**被占用的行数**算 | 连堂课只算 1 节，空闲数虚高 |
| ② | 连堂卡片只画在**起始行** | 中间几行没被标记占用，统计又漏算 |
| ③ | 把**截止**算成"占了一节课" | 与编辑页"截止不算占用"的口径**正好相反** |
| ④ | 只写时间的任务**画在第 3 节那一行、却让第 3 节算作空闲** | 屏幕上明明有卡片，数字说这节空着 |

**修法**：统一到一个口径函数 `resolveSpan(task)` —— **排版（`locateRow`）与统计（`occupiedRowsOfDay`）都必须走它**。

顺带把课表落点从"起点包含判定 / 就近吸附"改成**"取时间重叠最多的那一节"**：
旧口径会把卡片画到跟它时间对不上的一行，例：`09:55–10:55` 曾被吸到**第 4 节、重叠 0 分钟**，
现在落**第 3 节（10:00–10:45）、重叠 45 分钟**。

**一处容易被误改的细节**：**空档行（午休）照旧能接任务** ——
它不是一条假的横线，而是 `periodRows` 生成的一行、有真实时间区间、真的画在网格里，
而且**本来就不计入空闲**，所以往里面放卡片不会污染「空闲 N 节」。

> 这条也解释了一个容易误解的数字：**有「午休」空档行的那天，「空闲 N 节」的分母是 `13 − 1 = 12`**。
> **这是正确值，不是掉了一节课。**

### 3. 另外两个新功能

- **新建任务时的占用提示**：红字列出撞上的条目（`该时间段已被占用：08:30-09:55 光学实训（与 1 条日程重叠）`）
  ＋ 一个「换到最近的空闲**课节**」按钮。**只提醒、不阻断保存**（用户可能就是故意重叠）；
  区间用**半开 `[start,end)`**（首尾相接不算撞）；**截止只有一个时刻、不算占用时间段**；编辑时排除自己。
  避让只落在**课节开始时刻**，否则会给出 `09:57` 这种课间时刻、卡片又会被画错行。
- **用自己的 API Key 识别课表截图** + **DDL 到期微信服务通知**（`remind` 云函数）：
  模型能力**三态判定**（已知支持放行 / 已知纯文本模型**直接拦下、一个请求都不发** / 没收录的允许尝试）；
  图片**不落库、不进日志**（日志里只有 mime 与字节数）。提醒是**额度制**（一次性订阅授权一次只能发一条）、
  **幂等**（同一截止时刻只提醒一次）、**错误码分类**（`43101` 用户拒收 → 自动关掉该用户提醒；
  `47003` 模板字段不符 → 记录里带上"哪个字段、发了什么值"）。

## 五、和 Python 版的关系

| | Python / Streamlit 版 | 小程序版 |
|---|---|---|
| 场景 | 电脑浏览器，可多用户（空间码隔离） | 手机，每人用自己的微信身份 |
| 业务规则 | **唯一真源**（`config.py` / `planner.py` / `task_manager.py`） | 重写为 JS，逐条对照 Python 与单测 |
| 存储 | SQLite（服务器）/ JSON（单机） | 云数据库，按 openid 隔离 |
| AI | 智谱 / DeepSeek 可切 | 同左，Key 存云函数环境变量 |

移植时**有意保留的差异**（都写在对应文件头部注释里）：

- Python 用 tuple 返回 `(值, 错误)`，JS 没有 tuple → 统一改成数组；解析失败返回 `null` 而不是一对 `null`。
- 周次计算以**周一**为一周之始，与 Python 版一致；时区固定 **UTC+8**（云函数容器是 UTC，直接 `toISOString()` 会在 00:00–08:00 差一天）。

## 六、常见问题

**Q：提示「云开发未初始化，请检查 app.js 里的云环境 ID」**
`app.js` 里的 `ENV_ID` 还是 `YOUR-ENV-ID`，照第 2 步填上真实环境 ID。
   > 只有一个云环境时其实**可以不填**：程序会按默认环境初始化，并在控制台给一句中文提示。
   > 有多个环境、或控制台提示环境不存在时，再回来把环境 ID 填上。

**Q：右键「上传并部署」报「请在编辑器云函数根目录（cloudfunctionRoot）选择一个云环境」**
代码里的 `ENV_ID` 管的是**小程序运行时**读写哪个环境；开发者工具给 `cloudfunctions` 目录绑的环境是**另一处独立设置** —— 这个报错缺的是后者。按顺序试：
① 点工具栏「云开发」打开控制台 → **在左上角的环境下拉里选中你的环境** → **把控制台窗口关掉**，再回来右键上传（关掉重开这一步别省，工具需要重新同步）；
② 仍报错就右键 **`cloudfunctions` 文件夹本身**（不是里面的 `tasks`），找「选择环境 / 当前环境」一类的菜单项；
③ 还不行：检查开发者工具**登录的微信号**是不是拥有这个小程序的账号 —— 不是同一个号，那个环境在工具里根本不会出现。

**Q：AI 一直提示「AI 服务暂不可用」**
按顺序查：① 第 5 步的 Key 配了吗；② **两个**云函数都配了吗（`aiParse` 和 `aiDecompose` 环境变量不共享）；③ 云函数改了环境变量后要**重新部署**才生效；④ 到云开发控制台的云函数日志里看具体原因 —— 区分（未配 Key / Key 无效 / 额度不足 / 超时 / 解析失败）都写在日志里，但**不会**返回给前端（避免把厂商原始报错暴露出去）。

**Q：识别课表截图时提示「这个模型不支持识图」？**
这是**刻意拦下来的**，不是 bug。项目默认的文本模型（`glm-4.7-flash`）是纯文本模型，
拿它传图必然是白跑一次 + 一句看不懂的错，所以**一个请求都不发**、直接提示换模型。
识图请换成 `glm-5.3-flash`（原生多模态）或 `glm-ocr`（专做图文解析）。
没收录在名单里的模型一律**允许尝试** —— 新模型层出不穷，硬说"不支持"会挡人。

**Q：到期提醒没收到服务通知？**
先看小程序里 `remind` 的 `status` 返回的 `ready_reason`（那句就是给人看的），再照 `docs/到期提醒.md` 第 7 节的排查表对号入座。最常见的三个原因：① 模板 ID 没配或没重新部署；② 用户的订阅**额度用完了**（一次性订阅 = 授权一次只能发一条，这是平台规则）；③ 被微信回了 `43101`（用户拒收），此时云函数会自动关掉该用户的提醒，重新授权即可恢复。

**Q：数据和别人会串吗？**
不会。每个云函数只从 `getWXContext()` 取 `openid`，所有查询都带 `_openid` 过滤，前端传进来的身份字段会被显式剥掉。前提是集合权限按第 3 步设成「仅创建者可读写」。

**Q：为什么不做成「套一层网页」直接把 Python 版装进去？**
个人主体的小程序**不能用 `web-view`**（微信官方限制），所以无法把 Streamlit 页面套壳。这也是这一版把逻辑重写成云函数 + 小程序的原因。

**Q：免费额度够用吗？**
个人使用（几个人、几百条日程）够。具体额度与计费以微信官方文档为准 —— 我这里不写死数字，因为它会变。

**Q：.ics 文件从哪来？**
WakeUp 课程表、超级课程表等 App 都能导出 .ics。用法：把 .ics 文件**发到微信任意聊天（比如"文件传输助手"）**，然后在「我的 → 导入课表」里选择它 —— 小程序只能读聊天记录里的文件，不能读手机任意目录。

**Q：导入后课表是空的？**
看导入预览页显示的 `warnings`。常见原因是 .ics 里的课程没有 `RRULE`（只出现一次）或周次信息不全 —— 解析器不会猜，会把看不懂的行报出来而不是静默丢弃。
