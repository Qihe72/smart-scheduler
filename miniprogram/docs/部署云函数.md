# 部署云函数（微信开发者工具）

> 目标：把 `cloudfunctions/` 下的 **3 个**云函数跑起来，并给两个 AI 函数配上 DeepSeek 密钥。
> 全程只需要点鼠标 + 复制两段文本，不需要命令行。

**要部署的三个云函数**（缺一不可，名字必须与文件夹名一致）：

| 云函数 | 作用 | 关键依赖 |
|---|---|---|
| `tasks` | 任务增删改查 / 统计 / 设置 | 只读 `_openid`，不需要任何 key |
| `aiParse` | 自然语言 → 日程 | 环境变量 `ZHIPU_API_KEY`（推荐）或 `DEEPSEEK_API_KEY` |
| `aiDecompose` | 大任务拆解成子任务 | 同上（**两个函数都要各配一遍**） |

---

## 0. 前置检查（30 秒）

* [ ] 微信开发者工具已登录，项目根目录是 `miniprogram/`（里面有 `app.json`、`cloudfunctions/`）。
* [ ] `project.config.json` 里有 `"cloudfunctionRoot": "cloudfunctions/"` —— **没有这行就没有云函数右键菜单**（本项目已配好）。
* [ ] `app.js` 里的 `ENV_ID` 已从占位符 `'YOUR-ENV-ID'` 换成真实云环境 ID —— **没换的话所有云函数调用都会失败**。
* [ ] 已开通**云开发**（第一次点顶部「云开发」按钮会引导开通，选按量付费/免费额度即可）。
* [ ] 记下你的**云环境 ID**（形如 `cloud1-7gxxxxxxxxxxxx`），`app.js` 里的 `wx.cloud.init({ env })` 要填它。

> 云环境 ID 在哪看：云开发控制台 → 左上角环境名旁边，或「设置 → 环境 ID」。

## 1. 上传并部署 `tasks`（三个函数都要做一遍）

以 `tasks` 为例：

1. 在开发者工具左侧的**资源管理器**里找到 `cloudfunctions/tasks` 目录。
2. **右键这个目录**（不是里面的 `index.js`）。
3. 菜单里选 **「上传并部署：云端安装依赖（不上传 node_modules）」**。
   * ✅ 选这一项：云函数在云端 `npm install`，你本地不需要 `npm install`，也不用上传 `node_modules`。
   * ❌ 不要选「上传并部署：所有文件」—— 它会把本地 `node_modules` 一起传上去，慢且容易因为平台差异出错。
4. 右下角会弹出进度，等它变成 **「上传成功」**（第一次要装依赖，可能要 30~60 秒）。
5. 重复第 2~4 步，把 **`aiParse`** 和 **`aiDecompose`** 也部署一遍。

> **为什么必须「云端安装依赖」？**
> 三个函数的 `package.json` 里只有 **一个**依赖 `wx-server-sdk`（由云函数运行环境提供）。
> 云端安装能保证拿到与运行环境匹配的版本；本地装反而可能因为 Node 版本不同出问题。

### 部署成功的标志

云开发控制台 → **云函数** → 函数列表里能看到 `tasks` / `aiParse` / `aiDecompose` 三个，
且「最后更新时间」是刚刚。

## 2. 给 `aiParse` / `aiDecompose` 配置环境变量（**可选**，作为兜底）

**这一步现在是可选的。** Key 有**两级来源**，你至少要有其中一级：

| 来源 | 怎么来 | 谁买单 | 对用户 |
|---|---|---|---|
| **① 用户自填**（优先） | 用户在小程序「我的 → AI 设置」里填自己的 Key，存进 `settings` 集合 | 用户自己 | 谁填的用谁的，评审/同学不会烧机主额度 |
| **② 服务端预置**（兜底） | 就是本节要配的环境变量 | 你（机主） | 没填 Key 的用户自动用你的 |

**优先级：用户自填 > 服务端预置 > 报「AI 服务暂不可用」。**

> 只想给熟人用、不想垫额度？**什么都不配也行** —— 那时所有 AI 功能都要求用户先自己填 Key，
> 没填的人会看到"AI 服务暂不可用"。想开箱即用就配一个预置 Key 当兜底。

### 2.1 预置这一级用哪家服务商

代码里**没有写死任何一家**，由环境变量决定。推荐**智谱**（默认模型 `glm-4.7-flash`，目前免费），
DeepSeek 作为备选保留 —— 手上已有哪个 Key 就配哪个，**两个都配也行**。

| 环境变量 | 作用 | 建议值 |
|---|---|---|
| `ZHIPU_API_KEY` | 智谱开放平台密钥（推荐，免费） | 从 [bigmodel.cn 的 API Keys 页](https://bigmodel.cn/usercenter/proj-mgmt/apikeys)获取 |
| `DEEPSEEK_API_KEY` | DeepSeek 密钥（备选） | `sk-...` |
| `LLM_PROVIDER` | **可选**，显式指定用哪家 | `zhipu` 或 `deepseek` |
| `LLM_MODEL` | **可选**，覆盖模型名 | 例如 `glm-4.5-flash`、`deepseek-reasoner` |

**预置这一级选谁用「谁配了 Key 用谁」的规则**（实现在 `resolveProviderConfig()`，有自测覆盖）：

| 配了什么 | 实际使用 | 说明 |
|---|---|---|
| 只有 `ZHIPU_API_KEY` | **智谱** `glm-4.7-flash` | 推荐形态 |
| 只有 `DEEPSEEK_API_KEY` | **DeepSeek** `deepseek-chat` | 老用户不会有任何回归 |
| 两个都配了 | **智谱** `glm-4.7-flash` | 日志里会提示"检测到多个服务商" |
| 两个都没配 | 直接返回 `AI 服务暂不可用` | 不发网络请求 |
| `LLM_PROVIDER=deepseek` + 两个都配 | **DeepSeek** | 显式指定优先 |
| `LLM_PROVIDER=zhipu` + 只有 DeepSeek Key | **报错**（不偷偷换一家） | 日志点名缺 `ZHIPU_API_KEY` |
| `LLM_PROVIDER=openai`（不认识的名字） | 忽略该值 + 退回自动挑选 | 日志里说明支持哪些名字 |
| 任意情况 + `LLM_MODEL=xxx` | 用 `xxx` 作为模型名 | 试新模型不用改代码 |

> 模型名与价格会变，**以各家官方文档为准**。想换模型不必改代码：
> 在控制台把 `LLM_MODEL` 设成新模型名即可。

### 2.2 控制台在哪里配（逐步）

1. 开发者工具顶部点 **云开发** → 打开**云开发控制台**。
2. 左侧菜单点 **云函数** → 在函数列表里点函数名 **`aiParse`**。
3. 上方切到 **「配置」** 标签页（部分版本叫「函数配置」）。
4. 找到 **「环境变量」** 一栏，点 **「编辑」**（或「添加环境变量」）。
5. 按 **键 / 值** 各填一行，例如：

   | 变量名（Key） | 变量值（Value） |
   |---|---|
   | `ZHIPU_API_KEY` | `你的智谱密钥` |

   想同时留备选就再加一行 `DEEPSEEK_API_KEY`；想指定服务商再加 `LLM_PROVIDER = zhipu`。
6. 点 **「保存」**。环境变量改动会触发函数重新部署，**等状态变成「正常」再测**（约十几秒）。
7. 对 **`aiDecompose`** 重复第 2~6 步 —— **两个函数各配一次，环境变量不共享**（这是最容易漏的一步）。

> 小提示：密钥粘贴时别带上首尾空格或引号；`LLM_PROVIDER` 的值要是 `zhipu` / `deepseek`
> （大小写和空格会容错，但拼错名字只会被忽略并退回自动挑选）。

### 2.3 用户自填的 Key（不需要你做任何配置）

* 用户在「我的 → AI 设置」里填 Key → 前端调 `tasks` 的 `ai_config_save`
  → **Key 只在这一次上传**，存进 `settings` 集合（每人一条，**复用现有集合，不用新建**）。
* 之后每次 AI 调用，是 `aiParse` / `aiDecompose` **自己按 `openid` 去数据库读** Key，
  前端**不再**上传 Key —— Key 只在"保存"那一次经过网络。
* 回传前端的一律只有掩码（`****abcd`，末 4 位）与"有没有填"；返回对象还过一遍
  `stripSecrets()` 兜底。**Key 原文永远不回传给前端。**
* 三个 action：`ai_config_get` / `ai_config_save` / `ai_config_clear`
  （返回形状与字段见《数据库与索引.md》第五节）。
* 用户自填的 Key 失败时（填错/过期/额度用完），前端会收到
  **「你填的 AI Key 无法使用，请到「我的 → AI 设置」检查或重新填写」**；
  而**服务端预置**的 Key 失败仍只回「AI 服务暂不可用」—— 用户对预置 Key 无能为力，
  多说不泄露厂商内部信息的前提下也没用。这条区分**是契约的一部分**。

### 为什么 key 放在这里就安全

* 云函数的环境变量**只存在于服务端**，随函数一起在腾讯云机房运行。
* 小程序前端代码里**没有**这个 key，也无法通过任何接口读出来 ——
  前端只能拿到 `{ok:true, events:[...]}` 这种**结果**。
* `aiParse/index.js` / `aiDecompose/index.js` **只从 `process.env` 读**（`ZHIPU_API_KEY` /
  `DEEPSEEK_API_KEY`），既不接受入参里的 key，也不会把 key 写进返回值或日志
  （日志里只有**服务商名 + 模型名**，自测里有一条断言专门检查解析结果不含密钥值）。
* 代码与文档里**不出现任何真实 key**；`package.json` 里也只有 `wx-server-sdk` 一个依赖。
* ⚠️ **绝对不要**为了图省事把 key 写进小程序代码（`app.js` / `utils/`）——
  小程序包可以被下载反编译，等于把 key 公开发布。
* ⚠️ 也不要提交到 git：如果本地调试用过 key，确认它没被写进任何仓库文件。

## 3. 怎么在控制台看日志与报错

**最快的方式（推荐）**：开发者工具 → **云开发控制台** → **云函数** → 点函数名 → **「日志」** 标签。
可以按时间筛选，点开一条能看到 `console.log` / `console.error` 的完整输出。

**开发时更方便的方式**：开发者工具底部 **「调试器 → Network」**，或
**云开发控制台 → 云函数 → 日志**里按「最近 1 小时」筛选，边测边刷新。

我们的日志都带 **函数名前缀**，并会写明 **服务商/模型**（如 `zhipu/glm-4.7-flash`），一看就知道是谁打的。
**前端永远只收到 `AI 服务暂不可用`**，厂商原始报错只在日志里 —— 下面这些细节都只有你能看到：

| 日志片段 | 含义 | 怎么办 |
|---|---|---|
| `跳过 AI 调用：没有任何服务商配置了 API Key（请配置 ZHIPU_API_KEY 或 DEEPSEEK_API_KEY）` | 两个 Key 都没配 | 回到第 2 节配一个（推荐智谱） |
| `[aiParse] 跳过 AI 调用（来源=服务端环境变量）：没有任何服务商配置了 API Key（请配置 ZHIPU_API_KEY 或 DEEPSEEK_API_KEY）` | 既没人填自己的 Key，也没配预置 Key | 要么自己配一个（第 2 节），要么让用户去「我的 → AI 设置」填 |
| `（来源=用户自填）` / `（来源=服务端环境变量）` | **日志里的来源标注**：这次用的是谁的 Key | 排查"为什么突然不能用了"时先看这个 —— 用户自填的 Key 出问题只有他自己能改 |
| `[tasks] ai_config_save：已保存用户自填 Key（来源=用户自填，provider=...，masked=****abcd）` | 用户保存了自己的 Key | 正常。**日志里只有掩码，没有 Key 原文**（这是刻意的，别去加打印） |
| `[tasks] ai_config_clear：用户已清除自填 Key，回退到服务端预置` | 用户清掉了自己的 Key | 正常，之后他走预置 Key |
| `入参里出现了不该由前端指定的字段（apiKey, baseUrl, ...），已忽略` | 有人往 AI 云函数里塞了凭证或地址字段 | 正常会被忽略；若频繁出现，去查前端是否把 Key 当成每次请求的参数传了（设计要求：Key 只在保存时上传一次） |
| `跳过 AI 调用：LLM_PROVIDER 指定了 zhipu，但它没有配置 ZHIPU_API_KEY` | 指定了服务商却没配它的 Key | 补上该 Key，或把 `LLM_PROVIDER` 换成另一家 |
| `LLM_PROVIDER="openai" 不是支持的服务商，已忽略并改为自动挑选` | 服务商名拼错 | 改成 `zhipu` / `deepseek` |
| `检测到多个服务商都配了 Key（zhipu / deepseek），已选用默认推荐的 zhipu` | 两家都配了 | 想换一家就设 `LLM_PROVIDER`；否则可以无视 |
| `zhipu/glm-4.7-flash 请求失败：请求超时（>15 秒）` | 外网慢或模型排队 | 重试；持续超时看云函数「监控」的耗时曲线（记得把超时改成 20 秒） |
| `认证失败（HTTP 401 / 业务码 1000 / 身份验证失败）` | 智谱 Key 无效/过期（业务码 1000/1001/1003） | 重新复制智谱 Key，别带引号和首尾空格 |
| `认证失败，API Key 无效或已过期（HTTP 401 / ...）` | DeepSeek Key 无效（它没有业务码，靠 HTTP 状态） | 同上 |
| `额度/频率受限（HTTP 429 / 业务码 1113 / 您的账户已欠费...）` | 智谱**欠费**（1113）或限流（1302/1305/1308） | 去智谱后台充值 / 降低调用频率；日志会区分是欠费还是限流 |
| `请求过于频繁或额度不足（HTTP 429 / ...）` | DeepSeek 限流或余额不足 | 等一会儿再试，或去 DeepSeek 后台看余额 |
| `模型不存在（当前模型 "glm-4.7-flash" ... 业务码 1211）` | **智谱把"模型不存在"放在 HTTP 400 + 业务码 1211**（不是 404） | 检查模型名，或用 `LLM_MODEL` 换成可用模型 |
| `请求参数有误（HTTP 400 / 业务码 1210 ...）` | 请求体有问题（智谱 1210/1213/1214 等） | 多半是模型不支持某个参数 —— 日志里能看到完整 message |
| `拒绝了 response_format，去掉该字段重试一次` | 该端点/模型不支持 JSON 模式 | 正常兜底：自动去掉 `response_format` 重试一次，不影响结果 |
| 模型返回带全角标点（如 `"events"：`）也能解析 | 模型用中文输入法时的常见产物 | 已容错：全角引号 `“”`、全角冒号 `：`、全角逗号 `，` 与尾逗号都会修复后重新解析 |
| `服务商内部错误（HTTP 5xx）` | 服务商自己故障 | 稍后重试（这类不是你的 bug） |
| `无法从模型返回内容中解析出 JSON：...` | 模型没按要求返回 JSON | 日志里会打印返回内容的前 200 字，据此调整 prompt |
| `[tasks] 执行失败：...` | `tasks` 的兜底错误，后面跟着堆栈 | 看堆栈最后一行的行号定位 |
| `无法识别用户身份，请在小程序内调用` | **在控制台"测试"里直接点运行**时会出现 | 正常现象：控制台测试没有微信登录态，所以 `OPENID` 是空的 |

> 想手工试 `tasks`：控制台 → 云函数 → `tasks` → **「测试」** → 入参填
> `{"action":"list"}`。**注意**这种测试没有登录态，`OPENID` 为空会直接返回失败
> （这是设计如此，见《数据库与索引.md》第八节）。要真测就在小程序里点。

## 4. 常见错误与排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 右键目录**没有**「上传并部署」 | `project.config.json` 缺 `cloudfunctionRoot` | 加上 `"cloudfunctionRoot": "cloudfunctions/"`，保存后重开工具 |
| 报「请在编辑器云函数根目录（cloudfunctionRoot）选择一个云环境」 | `app.js` 里的 `ENV_ID` 管的是**运行时**用哪个环境；工具给 `cloudfunctions` 目录绑的环境是**另一处设置**，这里缺的是后者 | ① 「云开发」打开控制台 → 左上角**选中你的环境** → 关掉控制台重开，再右键上传；② 仍报错就右键 **`cloudfunctions` 文件夹本身**，找「选择环境 / 当前环境」类菜单项；③ 还不行：确认开发者工具登录的微信号就是拥有本小程序的号（不是同一个号，环境不会出现在工具里） |
| 报 `未开通云开发` / 提示开通 | 项目还没开通云开发 | 点顶部「云开发」按引导开通，选一个环境 |
| 报 `云环境 ID 不正确` / `env check invalid` | `app.js` 里的 `env` 还是占位符 / 填错 | 填控制台里真实的**环境 ID**（不是环境**名称**） |
| 报 `Cannot find module 'wx-server-sdk'` | 本地直接 `node index.js`，或上传时没选「云端安装依赖」 | 重新「上传并部署：云端安装依赖」；本地跑请用 `node _selftest.js`（它不需要云环境） |
| 报 `collection not exists` | 集合没建 | 控制台 → 数据库 → 新建 `tasks` 和 `settings`（见《数据库与索引.md》第三节） |
| 一直转圈然后超时 | 云函数默认超时只有 **3 秒**，而 AI 调用最长要 15 秒 | 控制台 → 云函数 → `aiParse` → 配置 → **超时时间改成 20 秒**；`aiDecompose` 同样处理。`tasks` 建议也调到 **5 秒**（`list` 要分页取全，数据多时可能超过 3 秒） |
| 所有按钮都失败、日志里 `list` 也报错 | `tasks` 没部署 / 部署的是旧版本 | 重新部署 `tasks`，看控制台函数列表的更新时间 |
| 能读到**别人**的任务 | ⚠️ 集合权限设成了「所有用户可读」 | 立刻改成**仅创建者可读写**（两个集合都要），见《数据库与索引.md》第三节 |
| AI 功能返回 `AI 服务暂不可用` | 没配任何 Key / 超时 / 网络失败 / Key 无效 / 额度不足 / 模型名不对 | 先看日志区分是哪一种（见第 3 节表格，日志会写明**来源**、服务商、模型与业务码） |
| **用户填了自己的 Key，还是失败** | ① Key 抄错/已过期/额度用完；② 他选的 `provider` 与 Key 不是同一家（例如填了智谱的 Key 却选了 deepseek）；③ 他填的模型名不对 | 让他打开「我的 → AI 设置」重新填一次；日志里 `来源=用户自填` 加业务码（1000/1003=认证失败、1113=欠费、1211=模型不存在、1302/1305=限流）能直接定位。**前端这时会看到"你填的 AI Key 无法使用…"那句文案** |
| 用户想换回你自己的额度 | 他有自填 Key，优先级高于预置 | 让他点「清除」（`ai_config_clear`），之后自动回退到服务端预置 Key |
| **导入后发现课程翻倍了** | 见下方专节 | 用 `import_replace`（替换）而不是再导一遍 |
| `import_replace` 报 "scope 只能是 'courses'" | `scope` 传了 `all` / `COURSES` / 带空格的值 | 这个参数是**精确匹配**的：必须正好是字符串 `courses`。接口刻意不提供"清空全部" |
| AI 明明配了智谱却报"没有任何服务商配置了 API Key" | 只给 `aiParse` 配了，**漏了 `aiDecompose`**；或变量名拼错；或配完没等重新部署 | 两个函数各配一遍，确认环境变量状态是「正常」 |
| AI 报"模型不存在（业务码 1211）" | 模型名写错 / 该模型账号无权限 | 检查 `LLM_MODEL`；不确定就先删掉它，用默认的 `glm-4.7-flash` |
| 日志里日期比实际早 8 小时 | 本地打印的 UTC 时间 | 正常：容器的时区是 UTC。业务代码已按北京时间 +8 折算，看到 `+08:00` 结尾的时间就是对的 |

### 「导入后发现课程翻倍了」怎么办

**为什么会发生**：课表导入走的是 `bulk_add`（批量新增）。早期它**不做去重** ——
所以同一份 `.ics` 导两遍，每门课就变成两条（周视图里每格两张一样的卡片）。
用户以为"重导 = 覆盖"，实际是"追加"，于是手工删半天。

**现在有两道保险，各解决一半问题**：

| 手段 | 解决什么 | 做不到什么 |
|---|---|---|
| `bulk_add` **自带去重**（标题 + 日期 + 开始时间全等 → 跳过并计入 `skipped`） | 从此**再导一遍也不会翻倍**，哪怕调用方用的是"追加"语义 | 不会删掉**旧的那份**内容（只挡新插入的重复） |
| `import_replace`（`scope:'courses'`） | **真正替换**：先删旧课表再插新的。适合"第一份导错了，要换成正确的" | 只删**课表类任务**（判据见下），不会动手工数据 |

**「课表类任务」的判据**：`repeat === 'weekly'` **且** `periods` 非空
（即 `.ics` 导入产生的那种）。用户手工加的日程 / DDL / 子任务**一条都不会被删**。
两个已知边界（完整说明见《数据库与索引.md》第六节）：

* 手工建的"每周重复 + 填了节次"的任务会被一起替换掉（它确实长得跟课表一样）；
* `.ics` 里**没写节次**的 weekly 课不算课表类 → 不会被替换删掉、会残留，只能手工删。
  这是刻意选的：**宁可少删，不可误删**。

**前端写确认框时注意**：`removed` 是**真实删掉的条数**，可以用它写"已替换 N 门课"。
`partial:true` 表示"删成功但插失败"（返回里 `removed` 与 `inserted` 都是真实数字），
这时**必须**提示用户"已删除 N 条、只补回 M 条，请重新导入"，不要显示成功。

## 6. 关于前端的联调测试（`utils/tests/`）

前端有一份 `utils/tests/ai_contract.js`，它把 `wx.cloud.callFunction` 接到云函数的 `main()` 上，
并临时替换 `module.exports.postJson` 来伪造服务端响应 —— 所以它能**零网络**跑通完整链路。
云函数这边有两条约定专门配合它（`cloudfunctions/_selftest.js` 里有断言钉住）：

1. **`postJson` 必须是 `exports` 的自有属性**：`chatCompletion` 内部写的是
   `exports.postJson(...)` 而不是本地的 `postJson(...)`。否则前端替换的是导出对象上的属性、
   内部却调用本地函数，替换会**静默失效**并真的发出网络请求。
2. **导出用 `Object.assign(exports, {...})`，不要整体替换 `module.exports`**：
   整体替换会让闭包里捕获的 `exports` 指向旧对象，同样使替换失效。

**怎么跑**：`utils/tests/run.js` 会**等异步契约跑完再汇总**（它 await 每个测试模块导出的
`done` promise），所以下面两种跑法都有效、结论一致：

```bash
node utils/tests/run.js              # 汇总入口：planner + tasks + AI 契约 + AI 页入口 + ics
node utils/tests/ai_contract.js      # 只跑 AI 契约（require.main === module 时自己汇总并给退出码）
```
