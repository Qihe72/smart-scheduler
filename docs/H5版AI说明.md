# 网页版 AI 助手（H5）：为什么单独做、怎么部署

> 一句话：小程序里不含 AI（个人主体申请不到「深度合成」类目），AI 功能搬到 H5，
> 通过一个只做转发的云函数 `aiHttp` 调 DeepSeek / 智谱。

## 1. 为什么不放在小程序里

微信的深度合成类目（AI 问答 / AI 换脸 / AI 绘画 / AI 创作）**仅向非个人主体开放**，个人主体小程序无法申请；驳回意见就是这句话。腾讯云开发官方文档给个人开发者的建议原文是：

> 对于个人客户，考虑到类目限制，建议使用 **H5 或公众号**（订阅号/服务号均可），或者小程序的**客服消息**等其他方式实现 AI 智能体的功能。

而小程序里打开网页只能靠 `web-view` 组件，`web-view` **同样只对非个人主体开放**。所以这条路不是「小程序里跳一下」，而是「AI 整体待在小程序外面」。

## 2. 结构

```
浏览器 / 微信内打开 H5
        │  POST { action:'parse', text }
        ▼
云函数 aiHttp（HTTP 触发，只做校验 / 限流 / 转发）
        │  cloud.callFunction
        ▼
aiParse / aiDecompose（提示词、模型名单、Key 全在这两个函数里，只有一份）
        │
        ▼
DeepSeek / 智谱
```

**Key 永远不进浏览器。** H5 页面里只有接口地址和一个可选口令。

`aiHttp` 自身不含任何 AI 逻辑：

- 校验：`action` 认 `parse` / `decompose`；`text` 非空且 ≤500 字；`title` ≤100 字；`deadline` 必须是 `YYYY-MM-DD`
- 口令：环境变量 `WEB_AI_TOKEN` 设了就要求请求头 `X-Web-AI-Token` 一致
- 限流：环境变量 `WEB_AI_RPM`（默认 12）每 IP 每分钟；**只在单个实例的进程内有效**，挡手滑连点，挡不住真正的分布式刷
- 转发：`parse → aiParse{text}`，`decompose → aiDecompose{title,deadline}`
- 内层 `{ok:false}` 以 HTTP 200 + `{ok:false,error}` 透传，网页能把「人话」直接显示出来

## 3. 部署（四步）

### 3.1 上传云函数

开发者工具 → 左侧 `cloudfunctions` → 右键 `aiHttp` → **上传并部署：云端安装依赖**。

（它不参与小程序代码包，重传小程序不需要带上它。）

### 3.2 给它一个 HTTP 地址

云开发控制台 → 云函数 → `aiHttp` → 找「HTTP 访问服务 / 云接入 / HTTP 触发」这类入口（不同版本位置不同），新增路径 `ai`，拿到形如：

```
https://<你的环境>.service.tcloudbase.com/ai
```

控制台里**没有**这个入口时，两条替代路线：

1. **云托管（Cloud Run）**：把同一个 `index.js` 包成一个小服务发布，自带 HTTPS 域名；
2. **腾讯云 CloudBase**：同一个 AppID 可关联一个 CloudBase 环境，那边有完整的「HTTP 访问服务」。

### 3.3 设环境变量（可选但建议）

云函数 → `aiHttp` → 版本与配置 → 环境变量：

| 变量 | 建议值 | 作用 |
|---|---|---|
| `WEB_AI_ORIGIN` | 你放 H5 的域名 | 收紧 CORS；留空等于 `*` |
| `WEB_AI_TOKEN` | 随便一串 | 防别人白嫖你的 AI 额度，网页端要填同一串 |
| `WEB_AI_RPM` | `12` | 每 IP 每分钟上限 |

### 3.4 把网页挂上去

云开发控制台 → 静态网站托管 → 上传本仓库 `web/ai/index.html`（或整个 `web/ai` 目录）→ 得到一个默认域名（形如 `xxx.tcloudbaseapp.com`，**不需要备案**）。

打开网页 → 展开「连接设置」→ 填接口地址（和口令，如果设了）→ 保存到本机 → 说一句话试试。

## 4. 本地怎么验

```bash
# 云函数逻辑（不需要云环境、不需要 npm install）
node preview/probe_ai_http.js          # 33 条断言

# 网页（换成本地地址即可静态预览）
cd web/ai && python -m http.server 8000
# 浏览器打开 http://127.0.0.1:8000/ ，连接设置里临时填真实接口地址
```

`probe_ai_http.js` 覆盖：CORS 预检、方法/口令/限流、请求体（含 base64）、字段校验、转发落点（`aiParse` / `aiDecompose` 与参数）、内层失败透传、字符串结果容错。

做了两次变异自检（改坏一处，看红的条数是否正好对上）：

| 变异 | 期望 | 实测 |
|---|---|---|
| 拆掉口令闸 | 正好红 2 条（P11/P12） | 31/33，红 P11/P12 ✅ |
| 拆掉限流 | 正好红 1 条（P27） | 32/33，红 P27 ✅ |

## 5. 边界（别指望它做这些）

- **没有识图**。课表截图识别要把节次映射成你真实的作息时间，H5 没有你的 `period_times`，排不进课表——请在小程序里做。
- **不落库**。H5 解析出来的结果只显示在页面上，靠「复制成文字」带回小程序；它不写你的数据库。
- **没有登录态**。谁打开都能用（除非设了 `WEB_AI_TOKEN`），用的是服务端的预置 Key，额度共用。
- 页面里的接口地址和口令存在浏览器 `localStorage`；无痕模式下写不进去，会退化成每次手填。

## 6. 和小程序的关系

- 小程序：课表周视图、任务、子任务、`.ics` 导入、教务系统复制导入、到期提醒、写系统日历、备份导出 —— **一个 AI 都没有**，按「效率工具」类目走。
- 网页：只做 AI 解析 / 拆解。
- 两边唯一的联系是「复制结果 → 手工录入」，不存在数据互通，也不需要互通。
