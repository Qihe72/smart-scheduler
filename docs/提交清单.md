## 二、数据库（三个集合）

云开发控制台 → **数据库** → 新建集合。名字**区分大小写**，不要写成 `Tasks`。

| 集合 | 现在的状态 | 权限（**很重要**） | 建议索引 |
|---|---|---|---|
| `tasks` | 已有 | **仅创建者可读写** | `_openid`；`_openid+date`；`_openid+done` |
| `settings` | 已有 | **仅创建者可读写** | `_openid`（**唯一**） |
| `reminders` | ⚠️ **本轮需新建** | **仅创建者可读写** | `_openid` |

**`reminders` 是做什么的**：`remind` 云函数用它记账 —— 「这条截止已经提醒过了」（幂等）与「这次下发失败的原因」。
建它之前 `remind` 会报 `collection not exists`。

**为什么 `reminders` 也要「仅创建者可读写」**：它记录了你的任务标题与截止时刻，
和 `tasks` 一样属于私人数据。默认的「所有用户可读」会让**别人**读到你的日程 —— 这是这类小程序最容易出的隐私事故。

**`reminders` 的索引**：`_openid` **单字段、非唯一**。为什么是它：`remind` 的所有查询都是
`where({_openid})`（每个用户只扫自己的记录），不加索引时记录一多就会明显变慢。

> 索引怎么加：数据库 → 选中集合 → **索引管理** → 添加索引 → 选字段 → 保存。
> 数据量小时不建也能跑，**但 `reminders` 会随提醒次数持续增长**，建议一次建好。
> 完整的字段表、权限设置步骤与索引理由见 `miniprogram/docs/数据库与索引.md`。

## 三、`remind` 云函数的环境变量

云开发控制台 → **云函数** → `remind` → **配置** → **环境变量** → 新增：

| 变量名 | 值 | 必填 |
|---|---|---|
| `REMIND_TEMPLATE_ID` | `Tie4p47PRO5I8cuu8LktzXgjgfvTJL4HrkAXiZwHY2s` | ✅ **必填** |

该模板的字段与语义槽位的对应关系（**默认映射已对齐这个模板，所以不需要配 `REMIND_FIELD_MAP`**）：

| 模板字段 | 类型 | 放什么 |
|---|---|---|
| `thing2` | `thing`（**20 权重 ≈ 10 个汉字**） | **提醒内容** → 任务标题（超长自动截断并补 `…`） |
| `date4` | `date`（年月日，**可带时刻**） | **日程时间** → 截止时刻，形如 `2026年10月16日10:30` |
| `short_thing19` | `short_thing`（**5 权重 ≈ 2 个汉字**） | **日程类别** → `截止` |

> ⚠️ **长度是按"权重"算的，不是按字符数** —— 这条是**真机实测**得出的，不是猜的：
> 我们发过 `提交实验报告（还剩30分钟）`，它按字符数只有 14 个、看着没超，却被微信拒了：
> `should be 5-20 characters (data.thing2)`。按「汉字与全角标点算 2、数字字母算 1」复算
> 这条 = 26 > 20，与报错完全吻合。**所以 `thing2` 的真实预算约等于 10 个汉字。**
>
> 也正因为这个预算太紧，"还剩 N 分钟"那种尾巴会把标题挤掉，**所以提醒内容只放标题** ——
> "什么时候到期"由 `date4` 表达。代码里已有按权重的截断与自检，超长会自己裁掉，
> 不需要你手工控制长度。

速记：`REMIND_TEMPLATE_ID` 就是「模板 ID」，字段名是**平台侧**定的 ——
**换模板时只改 `REMIND_FIELD_MAP` 环境变量，不用改代码、也不用重新发版小程序**。

> ⚠️ **模板 ID 与字段名必须和微信后台「订阅消息」里那个模板逐字对得上**。
> 模板 ID 抄错一个字，表现是「一条都发不出去」；对不上的后果与排查见
> `miniprogram/docs/到期提醒.md`（该文档由负责 `remind` 的人维护）。

**配完必须做的事**：环境变量改动会触发函数重新部署，**等状态变成「正常」再测**（约十几秒）。

## 四、上传后必须亲眼确认：定时触发器

这是**只有你能做、而且必须做**的一步：定时触发器如果没生效，`remind` 就是一个**永远不会自己醒来的函数**，
表现为「提醒功能看起来配好了，但一条都不会来」。

| # | 在哪里看 | 应该看到什么 |
|---|---|---|
| 1 | 云开发控制台 → 云函数 → **`remind`** → 「**触发器**」标签页 | 有一条 **`remindScan`**、类型 **timer**（定时触发） |
| 2 | 同一条触发器的详情 | 有 **「下次触发时间」**，且是一个**未来的、5 分钟粒度**的时刻（如 `10:35:00`） |
| 3 | 触发周期 | `0 */5 * * * * *`（7 位 cron：**每 5 分钟**一次） |

**看不到触发器怎么办**（按顺序试）：

1. 确认 `cloudfunctions/remind/config.json` 里有 `triggers` 段（本项目已写好，不要删）→ 重新「上传并部署」`remind`；
2. 部署完成后**关掉控制台再重新打开**（工具需要重新同步一次）；
3. 仍没有就手动补：控制台 → `remind` → 触发器 → 新建 → 类型选「定时触发」→ cron 填 `0 */5 * * * * *`；
4. **等过了「下次触发时间」**，回到 `remind` → **日志**：应能看到一轮 scan 的输出。
   如果日志里一轮都没有 → 触发器没真正生效，回到第 1 步。

## 四之二、AI 设置怎么填（填错了会看到误导性的报错）

「我的 → AI 设置」三格：**服务商 / 模型 / API Key**。三个要点：

1. **服务商必须与你 Key 的归属一致**，否则请求一定失败：
   - Key 以 `sk-` 开头 → 选 **DeepSeek**；
   - Key 形如 `<32 位十六进制>.<16 位字母数字>` → 选 **智谱**。
   不一致时页面会显示黄字提醒，并给一个「切到 X」按钮（**只改选中的服务商，不会自动保存**）。
2. **模型：留空即可**（留空 = 用该服务商的默认模型）。要自己填的话：
   - DeepSeek → `deepseek-flash`（**V4.1-Flash，原生多模态、可以识图**）；
   - 智谱 → `glm-4.7-flash`（免费档，**纯文本、不能识图**）；识图用 `glm-5.3-flash` 或 `glm-ocr`。
3. **宣传名不是 API 模型名**：例如 `DeepSeek-V4.1-Flash`、`deepseek-v4.1-flash` 写进 API 会报
   「模型不存在」，正确写法是 `deepseek-flash`（界面会提示，但**不会**替你改写）。
   已停服的旧名也别再用：`deepseek-chat` / `deepseek-reasoner`（2026-07-24 起停止服务）。

> 报错怎么看：2026-10-13 修过一处**误导** —— 以前只要你自填 Key，任何失败都显示
> 「你填的 AI Key 无法使用」，于是"模型名写错"会把人带去查 Key。现在**具体原因优先**
> （模型不存在 / 额度限流 / 参数有误 / Key 无效各自说各自的），只有无法归类的失败
> （超时、网络、返回不合法）才用通用文案。

## 五、真机验证清单（逐条打勾）

> 这份清单对应**本轮修的问题**，每一条都写清"怎么做"和"看到什么算过"。
> 建议在真机上做（模拟器与真机的差异恰恰是本轮问题的来源之一）。

### 5.1 课表显示

- [ ] **连堂两格高**：有一门三节连堂的课（如「应用光学实验」），卡片**占满 3 行**、中间没有断缝。
- [ ] **兜底行在第一行**：制造一条定位不到的条目（例如只写时间、且时间落在任何一节之外的空档里），
      它应出现在**表头正下方第一行的「其他时段」**，**不用滑到底**就能看到。
- [ ] **三种角标可区分**：同一屏里能看到「程 / 止 / 务」三种角标，**颜色不同**，页脚有对应图例。
- [ ] **落点与时间对得上**：随手加一条 `09:55–10:55` 的子任务，卡片应落在**第 3 节**那一行
      （10:00–10:45，重叠 45 分钟），**不是**第 4 节。
- [ ] **切回课表页会自己刷新**（tab 页切走再切回**不会**重跑 `onLoad`，所以靠 `onShow`）：
      在编辑页**删掉**一条 → 切回课表页，**不用下拉刷新**它就该消失；
      在编辑页**新增**一条今天的日程 → 切回课表页立刻看到它。
- [ ] **切回来不闪加载态**：第二次起切回课表页**不该**闪一下"正在加载课表"（只有首次进页面才显示）；
      万一刷新失败（断网），**旧课表要留在屏幕上**，不能被清空成错误页。

### 5.2 占用提示

- [ ] **红字出现**：新建一条任务，时间填成与已有课程重叠（如 `08:30–09:55`），
      时间栏下方出现红字 `该时间段已被占用：…（与 N 条日程重叠）`。
- [ ] **不阻断保存**：**照样能点保存并且保存成功**（这是刻意设计的：用户可能就是故意重叠）。
- [ ] **首尾相接不算撞**：把时间填成 `09:40–10:00`（紧接着上一节课结束），**不应**出现占用红字。
- [ ] **截止不算占用**：新建一条「截止（ddl）」，时间填在已有课程中间，**不应**出现占用红字。
- [ ] **避让按钮**：点「换到最近的空闲课节」→ 起止时间被换成**某个节次的开始时刻**（如 `11:45`），
      且换完后红字消失、卡片落在与时间对得上的行；
      当天确实没有整段空闲课节时，按钮**置灰**并说明原因。

### 5.3 导入课表（本轮的核心修复）

- [ ] **替换课表确认框的三个数字**：点「替换课表」后，确认框里的**「将替换 N 门课」**等数字是**真实条数**
      （不是写死的、也不是 0）；确认后课表内容确实换了。
- [ ] **手工日程与截止未被删**：替换**之前**手工加一条日程 + 一条截止，
      替换**之后**它们**都还在**（替换只删"每周重复且填了节次"的课表类任务）。
- [ ] **导入后作息表出现「已校准」**：「我的」页 → 作息表里，导入课表时识别出的节次带 **「已校准」** 标记，
      并且来源说明写着「当前作息 = 默认作息 + 导入课表时校准的 N 节」。
- [ ] **🔴 本轮的根因验收**：导入一份**作息与默认表不同**的课表后，
      加一条 `end_time = 12:00` 的截止 → 它应落在**第 5 节**那一行（校准作息 `11:45–12:25`），
      **而不是**掉进「其他时段」。
      （旧版必错：默认作息里 12:00 落在 11:40–14:00 的午休空档，任何一节都落不进去。）
- [ ] **两条导入路径都生效**：「追加导入」路径同样会让作息校准落库（追加一次后重看作息表）。

### 5.4 截图识课表

- [ ] **拍照 / 选图能进来**：点识图入口 → 拍照或从相册选一张课表截图 → 图片能显示出来。
- [ ] **纯文本模型被拦下**：把 AI 模型设成项目默认的 `glm-4.7-flash` 后点识图 →
      **不发请求**，直接提示换模型（不是转圈半天再报个看不懂的错）。
- [ ] **推荐模型能跑**：把模型换成 `glm-5.3-flash` 或 `glm-ocr` → 能返回候选课程列表。
- [ ] **勾选后能导入**：「替换课表」与「追加导入」两个按钮都能用，且导入结果与 5.3 的验收一致。
- [ ] **图片不落库**：识别完成后去云开发控制台看 `tasks` / `settings` 集合，**没有**任何 base64 或图片字段。

### 5.5 到期提醒

- [ ] **授权弹窗能弹出**：在小程序里点提醒的授权入口 → 弹出微信的订阅授权框。
      （**注意**：`requestSubscribeMessage` 在开发者工具里会报 `not supported in devtools`，**必须用真机测**。）
- [ ] **额度被记上**：授权一次后，页面显示的剩余次数 **+1**。
- [ ] **收到了**：造一条 5 分钟后到期的截止 → 等定时器跑一轮 → 手机收到服务通知。
- [ ] **只收到一次**：再等 5 分钟、10 分钟，**不会**重复轰炸（同一条截止只提醒一次）。
- [ ] **收不到时的降级**（**这条要专门验**）：不配模板 ID、或提醒额度为 0 时，
      小程序**内**要有提示，而不是静默什么都不发生 —— 降级方案刻意不依赖微信通知。
- [ ] **失败留痕**：如果微信回了错误，去 `reminders` 集合看记录里有没有写明**哪个字段、发出去的是什么值**
      （这是排查模板字段问题的唯一手段）。
