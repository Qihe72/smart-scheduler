# 智能日程管家 · 部署指南

> 面向场景：**把项目交出去给评审看**。评审不会在你电脑前面坐着，所以要么他连你的 WiFi（路线 A），要么你给他一个公网地址（路线 B），要么他拿到一个镜像自己跑（路线 C）。
>
> 三条路线**互相独立**，按需要挑一条即可。每条都写清三件事：**在你自己电脑上敲什么 → 在哪里点什么 → 看到什么算成功**。

---

## 0. 先说清楚：这三个部署文件放哪

本次交付的部署文件（都在本指南所在目录的上一级）：

```
Dockerfile              # 路线 C：容器镜像定义
docker-compose.yml      # 路线 C：可选的整套编排（含数据卷与 .env）
.dockerignore           # 构建时排除 data/、.env 等私有文件
.streamlit/config.toml  # 三条路线都用：服务器/浏览器配置
requirements.txt        # 三条路线都用：依赖清单
docs/部署指南.md         # 本文件
deploy_check.md         # 部署前检查清单（谁做什么）
```

**放到项目里怎么放**（不改任何现有文件的逻辑，只新增/覆盖配置文件）：

| 文件 | 目标位置 | 动作 |
|---|---|---|
| `Dockerfile` | `smart-scheduler/Dockerfile` | 新增 |
| `docker-compose.yml` | `smart-scheduler/docker-compose.yml` | 新增（不用 compose 可以不拷） |
| `.dockerignore` | `smart-scheduler/.dockerignore` | 新增 |
| `.streamlit/config.toml` | `smart-scheduler/.streamlit/config.toml` | **覆盖**（原文件只有 `[theme]`，新文件把 4 个原键原值原样保留，只多了 `[server]`/`[browser]`） |
| `requirements.txt` | `smart-scheduler/requirements.txt` | **覆盖**（原 3 项全保留，新增 1 项可选依赖 `segno`） |

> 注意：`data/` 和 `.env` **不要**拷进交付目录，它们是你本机的私有数据（`.gitignore` 里已经排除）。云端/容器首次启动本来就该是空数据。

## 路线 A：局域网 —— 手机连同一个 WiFi 打开 + 扫码

**适用**：评审就在你旁边（或同一间教室/宿舍），最省事、不用账号、不用花钱。**前提是电脑得开着**。

### A-1 在你自己电脑上敲什么

方式一（推荐，就是平时那种）：

```
双击  启动.bat
```

方式二（想自己指定监听地址时用）：

```bat
cd smart-scheduler
pip install -r requirements.txt
streamlit run main.py --server.address=0.0.0.0 --server.port=8501
```

> 项目里一共 8 个 `.py`：`main.py`（入口）、`ui_components.py`（界面）、`task_manager.py`（数据）、`importer.py`（导入）、`ai_parser.py`（AI）、`planner.py`（本周空档 vs 要做的事）、`config.py`（常量）、`launcher.py`（一键启动）。它们必须在**同一个目录**下 —— 少任何一个（例如漏拷 `planner.py`），应用还是能启动，但对应功能会**静默失效**（`try/except ImportError` 把错误吞掉了），页面不会给你报错。用 Docker 的话 Dockerfile 已经逐个列全了；改完代码后可以跑一次交付目录里的 `verify_build.py` 复核。

说明：`launcher.py` 会把命令行参数原样转给 streamlit（`%*`），所以加了参数的双击启动也可以这样写：

```bat
python launcher.py --server.address=0.0.0.0
```

> **为什么要显式写 `--server.address=0.0.0.0`？**
> 本机实测 Streamlit 1.64.0 的默认行为就是监听 `0.0.0.0`（`netstat -ano | findstr :8501` 能看到 `TCP 0.0.0.0:8501 LISTENING`），所以**默认已经能被手机访问**。
> 但 Streamlit 官方文档里 `server.address` 的默认值写的是 “(unset)”，社区也一直在讨论把它收紧成只监听 localhost。显式写上这两个字，行为就不会随版本升级漂移——**这是全篇唯一一处需要你记住的“保险动作”**。

### A-2 在哪里点什么

1. 电脑浏览器打开 `http://localhost:8501`（双击启动的话会自动弹出来）。
2. 左侧边栏往下拉，展开 **「📱 手机上使用」**。
3. 里面会显示一个形如 `http://172.30.38.197:8501` 的地址（`_local_ip()` 用 UDP 探测路由出口，不会真的发包）。
   - 装了 `segno` 的话，地址下面还有一张**二维码**，手机相机/微信扫一下就直接打开；
   - 没装 segno 会提示 `pip install segno`，装上刷新页面就出二维码（`pip install segno`，纯 Python、无依赖）。

### A-3 点完看到什么算成功

- 手机浏览器打开那个地址后，看到的是**同一个页面**：顶部 5 个 metric（📋 总任务 / ✅ 已完成 / 🕒 待办 / ⏰ DDL / 🎓 已结课）、周课表表格；
- 侧边栏里 **「📱 今日」** 视图在手机上最好用（一屏读完今天几节课、几点、在哪）；
- 可以在手机浏览器菜单里选「**添加到主屏幕**」，用起来跟 App 一样；
- 反过来验证一下：在手机上添加一条日程 → 电脑页面刷新后也能看到（同一份 `data/schedules.json`）。

### A-4 手机打不开时怎么排查（按顺序试）

| # | 检查 | 具体命令 / 动作 | 看到什么说明什么 |
|---|---|---|---|
| 1 | 是不是同一个 WiFi | 手机看 WiFi 名称；电脑 `ipconfig` | 电脑 IPv4 地址应是 `192.168.x.x` / `172.x.x.x` 这类**内网**地址；如果是 `169.254.x.x` 说明没连上网 |
| 2 | 手机是不是用了流量/内网隔离 | 手机上关掉「移动数据」，只留 WiFi | 很多校园网/公共 WiFi 开了**AP 隔离**，同一 WiFi 也互相 ping 不通 —— 换成手机热点让电脑连，就能绕过 |
| 3 | 服务有没有真的监听所有网卡 | 电脑上：`netstat -ano \| findstr :8501` | 出现 **`TCP 0.0.0.0:8501 LISTENING`** 才对；只出现 `127.0.0.1:8501` 就是没监听外部 → 加 `--server.address=0.0.0.0` 重启 |
| 4 | 端口对不对 | 侧边栏显示的端口 vs `netstat` 里的端口 | `launcher.py` 在 8501 被占用时会**自动顺延到 8502/8503…**，地址里的端口要跟着改 |
| 5 | Windows 防火墙 | 「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」，找到 **Python**，勾上 **专用**（专用网络） | 首次启动时如果弹过「是否允许 Python 通信」，当时点了「取消」的话手机就永远连不上；也可以直接在弹窗里勾「专用网络」后点「允许访问」 |
| 6 | 用命令行临时放行（需要管理员 PowerShell） | `netsh advfirewall firewall add rule name="SmartScheduler 8501" dir=in action=allow protocol=TCP localport=8501` | 加完立刻能用；演示完删掉：`netsh advfirewall firewall delete rule name="SmartScheduler 8501"` |
| 7 | 从电脑自己验证一次 | `curl http://172.30.38.197:8501/_stcore/health`（地址换成 `ipconfig` 里的） | 返回 `ok` 说明服务没问题，问题在手机↔电脑的网络/防火墙 |
| 8 | 都不行时的兜底 | 换**手机热点**：电脑连手机热点，重开应用看新地址 | 能通就是原 WiFi 的问题（AP 隔离 / 访客网络） |

> ⚠️ 安全提醒：这条路线下**同一 WiFi 里的任何人都能打开你的日程**（`data/schedules.json` 就是明文 JSON）。演示给评审看没问题，长期开着要记得关。

## 路线 B：Streamlit Community Cloud —— 免费公网 HTTPS 地址

**适用**：评审不在身边，你把一个 `https://xxx.streamlit.app` 链接发给他，他用手机 4G 就能看。**不花钱，但有三个必须知道的坑**（见 B-5、B-6、B-7）。

### B-1 先把仓库推到 GitHub（GitHub 网页上点，不是敲命令）

```bat
cd smart-scheduler
git init
git add .
git commit -m "smart-scheduler: streamlit app"
git branch -M main
git remote add origin https://github.com/<你的用户名>/smart-scheduler.git
git push -u origin main
```

**推之前一定要先确认这三件事**（不然你的 API Key 会公开在 GitHub 上）：

```bat
git status --short        :: 确认列表里没有 .env
git check-ignore -v .env data/schedules.json data/settings.json
```

第 2 条命令每条都该打印出「被 `.gitignore:N` 排除」；如果没有输出，说明没被忽略，**先别 push**。

> 🔴 **万一已经把 Key 推上去了**：立刻去 DeepSeek 控制台**吊销那个 Key**、重新生成一个 —— 删提交没用，GitHub 的历史和 fork 里还留着。新 Key 只放进 `.env`（本地）或 Streamlit Secrets（云端），永远不进 git。

### B-2 在 GitHub 上点哪里

1. 打开 https://github.com/new
2. **Repository name** 填 `smart-scheduler`
3. 选 **Public**（Community Cloud 部署公开仓库最省事；私有仓库也能部署，但要额外授权，见下）
4. **不要**勾 “Add a README file” / “Add .gitignore”（本地已经有了，勾了会冲突）
5. 点 **Create repository**，然后按网页提示把上面那段 `git push` 跑完

### B-3 在 Streamlit 上点哪里

1. 打开 https://share.streamlit.io ，点 **Continue with GitHub** 登录（第一次要授权 Streamlit 读你的仓库；私有仓库需要额外授予 `repo` 权限）。
2. 右上角 **Create app** → 选 **Deploy a public app from GitHub**。
3. 三个框这么填：
   - **Repository**：`<你的用户名>/smart-scheduler`
   - **Branch**：`main`
   - **Main file path**：`main.py` ← 注意必须是 `main.py` 这个入口文件名
4. 点 **Advanced settings…**（**别跳过这一步**）：
   - **Python version**：选 **3.12**。
     本项目 README 里写的是本机开发用的 **Python 3.14.0**，但 Community Cloud 明确只支持「仍在接收安全更新的正式版本」，能不能选到 3.14 取决于平台当时的状态 —— **选 3.12 最稳**（`requirements.txt` 只要求 ≥3.10，代码里没有 3.13/3.14 专属语法）。
   - **Secrets**：把下面这段粘进去（这就是「配置 AI」在云端的方式）：

     ```toml
     DEEPSEEK_API_KEY = "sk-你的真实key"
     ```

     为什么这样写就能用：Streamlit 的 secrets **根级键会同时变成环境变量**，而项目 `config.py` 读的正是环境变量：

     ```python
     DEEPSEEK_API_KEY = (os.getenv("DEEPSEEK_API_KEY") or "").strip()
     ```

     所以**不需要改任何代码**。注意键名要写成大写 `DEEPSEEK_API_KEY`（和 `.env.example` 里一致），值要用**双引号**包起来。
   - 本地开发时对应的是 `.streamlit/secrets.toml`（已在 `.gitignore` 里，不会上传）。
5. 点 **Deploy!** → 等 1~3 分钟（首次要装依赖）。页面会从 “in progress” 变成可以正常交互的界面。

### B-4 点完看到什么算成功

- 浏览器地址栏是 `https://<应用名>.streamlit.app`（**HTTPS，手机 4G 也能开**）；
- 页面正常渲染：顶部 5 个 metric、周课表区域；
- 日志区（右下角 **Manage app** → 日志）**没有** `ModuleNotFoundError`；
- 侧边栏「自然语言输入」里敲一句「明天下午三点开组会」，能返回解析卡片 → 说明 Secrets 里的 Key 生效了。
  - 如果提示「未配置AI服务」：回 **Manage app → Settings → Secrets** 检查键名/引号，改完点 **Reboot app**（改 Secrets 不会热生效）。

### B-5 ⚠️ 云端首次启动是「空数据」（不是 bug）

`data/schedules.json` 和 `data/settings.json` 都在 `.gitignore` 里，**不会上传到 GitHub**。所以云端第一次打开时：

| 你会看到 | 为什么 | 怎么处理 |
|---|---|---|
| 总任务 0、周课表全空 | 仓库里没有 `data/` 内容，`config.py` 的 `os.makedirs(DATA_DIR, exist_ok=True)` 会新建空目录 | 正常，继续下一步 |
| 学期起点是默认值 `2026-09-07` | `data/settings.json` 不存在，走 `config.SEMESTER_START_DEFAULT` | 在侧边栏「学期设置」里改成你的真实开学第一周周一 |
| 「🕳️ 本周空档」那栏提示「另有 N 件没写预计耗时」 | 任务上的「预计耗时」字段（`estimate_min`）默认是空的，`planner.py` 刻意**不替你猜**耗时 | 设计如此，不是 bug；想让它给结论就给任务填上耗时 |

**云端导入课表怎么导**：侧边栏的**上传课表**区块（`.ics` / `.csv` / `.json` 自动识别）—— 注意 `*.ics` 也在 `.gitignore` 里，仓库里没有你的课表文件，所以要把本机的 `.ics` **从电脑上重新上传一次**；导入后逐条确认、落盘，周视图就填满了。

### B-6 ⚠️ 免费实例会休眠

- 一段时间没人访问（官方口径是**闲置约 12 小时**，具体以平台当前策略为准）后应用会 **sleep**；
- 评审再打开时看到的是 **「Zzz / This app has gone to sleep」** 加一个按钮 → 点 **「Yes, get this app back up!」**，等十几秒到一分钟就恢复了；
- 所以：**演示前自己先点一次把应用唤醒**，别让评审当第一个点的人；
- **数据不会因为休眠而消失**（休眠只是停容器，磁盘还在），但见下一条。

### B-7 🔴 为什么它不适合「多人同时写」—— 三条硬伤

这个项目的数据层是**单文件 JSON + 全量重写**，这个取舍在本地（一个人、一台电脑）是对的，但搬到公网就暴露了：

1. **单文件 JSON，没有并发控制。**
   所有写入都是「读整个文件 → 改 → 整个文件写回」（`task_manager.py` 用临时文件 + `os.replace` 做原子替换，防的是「写坏文件」，防不住「两个人同时写」）。两个人同时点「确认添加」时，后写的那次会**把前一次的结果整体覆盖掉** —— 表现就是「我明明加了，刷新后没了」。
2. **云端文件系统是临时的（ephemeral）。**
   容器一重启、代码一 push 触发重新部署，`data/*.json` 就**回到仓库里的状态（空）**。也就是说云端的日程随时可能被重置 —— 演示可以，长期记事儿不行。
3. **没有登录、没有权限。**
   拿到 `https://xxx.streamlit.app` 链接的**任何人**都能看、也能改、也能删你的日程和课表；`st.session_state` 只是每个浏览器会话各一份的临时状态，**不是账号系统**。

因此，**这条路线请这样用**：
- 展示用：先在本机把状态调好，用**导出 JSON 再导入**（侧边栏导出/导入区）来准备演示数据；
- 想让评审自己上手点两下，**约定好同一时间只有一个人操作**；
- 真正的「多人共用」需要把存储换成数据库 + 加登录 —— 这是 README「后续计划」里的事，不是这次交付的范围。

## 路线 C：Docker —— 一条命令跑起来，数据挂在卷里

**适用**：评审/同学机器上有 Docker，你想给一个「不装 Python 也能跑」的包；也适合自己长期在后台跑（`restart: unless-stopped`）。

### C-0 前置

在项目根目录（`Dockerfile` 所在目录）打开 PowerShell / 终端，先确认：

```bat
docker --version
docker info
```

`docker info` 能打印 Server 段信息才算 Docker 真的在跑（Windows/macOS 要**先启动 Docker Desktop**）。

### C-1 构建

```bat
cd smart-scheduler
docker build -t smart-scheduler:1.0 .
```

- 第一次大概 1~3 分钟（要拉 `python:3.12-slim`、装 streamlit）；
- 结束时看到 `naming to docker.io/library/smart-scheduler:1.0` 附近有 `DONE` 就是成功；
- 想确认镜像在：`docker images | findstr smart-scheduler`。

### C-2 运行（推荐写法：数据挂卷 + 传 Key）

```bat
docker run -d --name smart-scheduler ^
  -p 8501:8501 ^
  -e DEEPSEEK_API_KEY=sk-你的真实key ^
  -v smart-scheduler-data:/app/data ^
  --restart unless-stopped ^
  smart-scheduler:1.0
```

（macOS / Linux / Git Bash 把行尾的 `^` 换成 `\`，写成一行也可以。）

逐个参数什么意思：

| 参数 | 作用 | 不写会怎样 |
|---|---|---|
| `-d` | 后台运行 | 前台跑，关掉终端就停 |
| `--name smart-scheduler` | 给容器起名，后面 `logs`/`stop` 都用它 | 只能拿容器 ID |
| `-p 8501:8501` | 宿主机 8501 → 容器 8501 | 浏览器打不开 |
| `-e DEEPSEEK_API_KEY=...` | 注入 API Key（`config.py` 读的就是这个环境变量） | AI 自然语言功能提示未配置，其他功能照常 |
| `-v smart-scheduler-data:/app/data` | **把数据目录挂出来**（具名卷） | **容器一删/镜像一重建，课表和日程全丢** |
| `--restart unless-stopped` | 开机/崩溃自动重启 | 电脑重启后要手动 `docker start` |

**关于 `-v` 的两种写法**：

```bat
:: ① 具名卷（推荐 Windows/macOS，不用管路径权限）
-v smart-scheduler-data:/app/data

:: ② 绑定宿主机目录（想直接看到文件、想手动备份时用；目录必须先存在）
mkdir D:\smart-scheduler-data
-v D:\smart-scheduler-data:/app/data
```

> 🔴 **Linux 用户注意**：绑定宿主机目录时，容器里的进程是 **root**（本 Dockerfile 没有建普通用户），写出来的 `schedules.json` 属主是 `root:root`，你在宿主机上用普通账号可能改不动/删不掉。要避免就先把目录放开：`sudo chown -R 1000:1000 ./data`，或者干脆用具名卷。Windows / macOS 的 Docker Desktop 有文件共享层，一般遇不到这个问题 —— 但**这条我没法在你的机器上验证**，第一次挂载后请按「验证命令」第 5 条试一次。

**换了端口怎么办**（8501 被本机已有的 Streamlit 占用时）：

```bat
docker run -d --name smart-scheduler -p 8502:8502 -e PORT=8502 ^
  -v smart-scheduler-data:/app/data smart-scheduler:1.0
```

`-e PORT=<端口>` 会传给 `CMD` 里的 `--server.port`（Dockerfile 用 `ENV PORT=8501` + `${PORT}` 做的，默认还是 8501）。

**用 `docker-compose.yml` 更省事**（Key 从 `.env` 读、数据卷、重启策略都写好了）：

```bat
docker compose up -d          :: 启动（首次会 build）
docker compose logs -f        :: 看日志（Ctrl+C 退出看日志，容器继续跑）
docker compose down           :: 停止并删容器（具名卷保留，数据不丢）
```

### C-3 点完看到什么算成功

1. 浏览器打开 `http://localhost:8501` → 页面正常渲染（顶部 5 个 metric、周课表区域）；
2. `docker ps` 里 `STATUS` 一列显示 **`Up ... (healthy)`**（健康检查要等 30~40 秒才会第一次跑，先 `(health: starting)` 是正常的）；
3. 手机（同一 WiFi）能打开 `http://<电脑局域网IP>:8501`；
4. 在页面里加一条日程 → 容器重建后**还在**（见验证命令第 5 条）；
