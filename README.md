## 一、为什么做这个：一个真实存在的痛点

我是一名大二学生，我的时间不是"几点开会"，而是**一张按节次排的课表 + 一堆交错出现的 DDL**。为了做这个项目，我先看了自己实际是怎么"记事情"的：

| 我试过的工具 | 它的问题（我自己的使用感受） |
|---|---|
| 手机日历 | 加一件事要填标题、选日期、选起止时间、选重复… **填一次 30 秒**，一句话的事被拆成五步表单 |
| 待办清单类 App | 只有"清单"，没有**时间轴**——看不出"周四上午三四节有课，这一天还剩哪段空着" |
| 课程表类 App | 只管上课，**不管作业和 DDL**，而 DDL 才是大学生焦虑的来源 |
| 备忘录 | 能记但不会提醒，也不会排 |

所以我想要的其实是一件很具体的事：

> **用一句自然语言把事情说出来 → AI 把它变成课表上的一条安排 → 我确认一下 → 它就在那儿了。**

三个关键设计就从这里来：

1. **时间刻度必须是"节次"，不是"上午/下午"** —— 大学生的生活是按第几节课走的。"周三下午两点到三点四十"和"周三第 7-8 节"是同一件事，但后者才是我看得懂的表达，而且**三节连堂**（第 7-9 节）必须能一眼看出占了三个格子。
2. **AI 解析的结果必须让我过一眼再落盘** —— AI 算错日期是常态。所以解析结果是**逐条确认卡片**（可以改、可以删），点"确认添加"才写进数据。
3. **数据必须留在我自己的电脑上** —— 课表、作业、DDL 都是私人信息，所以整个项目用本地 JSON 文件存储，不需要注册账号、不上任何服务器。

## 三、设计思路（每个决策背后的理由）

### 3.1 三层架构，依赖单向

```
main.py（页面装配，不碰业务逻辑）
   │
   ├── ui_components.py   界面：所有渲染与交互（不直接读写数据文件）
   ├── task_manager.py    数据与领域规则：增删改查、周次匹配、状态判定
   └── ai_parser.py       唯一的网络出口：调用 DeepSeek，文本 → 结构化数据
            │
        importer.py       多格式导入：.ics / .csv / .json → 任务
            │
         config.py        所有常量的唯一来源（作息表、类型、优先级、路径）
```

**为什么这样分**：界面层永远只调用 `task_manager` 的函数，不碰 JSON；AI 层只负责"文本 → dict"，不负责写盘。这样换界面（比如以后做小程序）时，`task_manager` / `importer` / `ai_parser` 可以整个复用。

### 3.2 为什么让 Python 算日期，而不是让 AI 自己推

LLM 最容易出错的地方就是**相对日期换算**（"下周三"是几号）。我的做法是**不给它猜的机会**：

1. 每次调用前，Python 先算出**日期参考表**注入 system prompt：今天是几号周几、明天/后天/大后天、本周一到周日、下周一到周日的**绝对日期**；
2. 再动态生成 **3 条 few-shot 示例**（示例里的日期也是按今天算好的真实日期）；
3. 配上硬规则：这周五若已过则顺延到下周、只写月日则取"今天之后最近的那一年"、十二小时制"下午/晚上 +12"、"半=30 分、一刻=15 分"。

实测结果（`今天 = 2026-09-22`）：输入"明天下午三点开组会，这周五前交实验报告，10月15号上午九点半体检" → 得到 `09-23 15:00`、`09-25`（DDL）、`10-15 09:30`，**三条全对**。

### 3.3 为什么 AI 返回要"容错解析"

模型返回的 JSON 经常带瑕疵：外面裹 ```` ```json ````、前后有解释文字、尾逗号、中文引号。所以解析做了**四级降级**（整段 → 剥代码块 → 截取最外层大括号 → 修尾逗号/中文引号），每级都用 `try-except` 包住 `json.loads`，全失败就返回友好错误而**不抛异常**。

### 3.4 为什么"已结课"是实时算的，而不是写进数据

这是我最想强调的一个设计取舍。最直觉的实现是"结课了就把 `done` 设成 true"，但这个项目里侧边栏有个**「一键清空已完成任务」**按钮——它是**删除**已完成的任务。如果自动把整学期的课标成"已完成"，用户点一下那个按钮，**一学期的课表就没了**。

所以"已结课"是按当前周次**实时计算**的派生状态：不污染数据、改学期起点或周次时会自动跟着变。

同理，三种状态刻意分开，因为**粒度不同**：
- **已结束** = 这一次课过点了（下午三点时，今早的课就是已结束）
- **已结课** = 整门课的最后一次课上完了
- **已完成** = 用户手动打勾

而**自己手动加的一次性日程永远不会自动结束**（哪怕日期已经过了），必须手动处理——因为"昨天下午三点的会议"到底是没去还是已经做完了，只有人知道。

## 四、我遇到的问题与解决过程

> 这一节是项目的核心。下面每一条都是**真实发生**的：现象 → 定位 → 根因 → 修复 → 验证。
> 大部分问题不是"看代码看出来的"，而是**写自动化测试 + 用真实课表跑**时暴露的。

### 问题 1：数据文件带 BOM，程序静默读空

- **现象**：程序看起来正常，但任务永远是 0 条。
- **定位**：测试里断言"初始应为空列表"通过了，我却起疑——因为我先前明明写进去过数据，于是直接打印文件原始字节：`b'\xef\xbb\xbf[]'`。
- **根因**：Windows PowerShell 的 `Set-Content -Encoding utf8` 会写 **UTF-8 BOM**，而 Python 用 `encoding="utf-8"` 读取时把 BOM 当成非法字符，`json.loads` 抛异常，被我的容错逻辑吞掉 → 返回 `[]`。**最危险的是它"看起来能用"**。
- **修复**：写入端保证无 BOM；读取端改用 `utf-8-sig`（兼容带 BOM 的文件）。
- **验证**：既断言文件字节是 `b'[]'`，又单独造一个带 BOM 的文件验证能被正确读出。

### 问题 2：AI 说"DDL"，程序却存成了"日程"

- **现象**：从自然语言添加"交实验报告"，最终存进去的 `type` 是 `event` 而不是 `ddl`（红色卡片变成了蓝色）。
- **定位**：集成测试里断言类型，打印落盘结果，看到 `(3, '真实DDL', 'event', ...)`。
- **根因**：中文标签映射表里我只写了小写 `"ddl"` 和中文 `"截止"`，而模型返回的是大写 `"DDL"`，查表失败后**静默回退成默认值 `event`**。
- **修复**：映射改成大小写容错（先精确、再转小写），并抽出 `type_to_const()` / `priority_to_const()` 供全项目共用。
- **验证**：`DDL / ddl / Ddl / Event / Low` 等写法逐一断言。

### 问题 3：错误处理把"页面刷新"也吞掉了

- **现象**：点"添加任务"后提示成功，但页面不刷新，新任务要手动刷新才出现。
- **定位**：测试里点击按钮后没有触发 rerun 信号。
- **根因**：我给每个区域加了错误边界（`safe_render`），任何异常都渲染成友好错误卡片。但 **Streamlit 的 `st.rerun()` 本身就是通过抛异常实现的**（`RerunException`），被我的 `except` 当成普通错误吞了——**"防崩溃"顺手把"刷新"也防掉了**。
- **修复**：错误边界识别控制流异常并原样抛出；先尝试 import 真实异常类做精确判断，同时保留按类名兜底（因为不同 Streamlit 版本类所在的模块路径不同）。
- **验证**：分别构造"普通异常→显示错误卡片"和"Rerun 信号→必须抛出"两种断言。

### 问题 4：只是打开编辑框再保存，就改坏了数据

- **现象**：一条开始时间 `15:00`、**没有结束时间**的日程，点开编辑再保存，就变成了 `15:00-10:00`。
- **定位**：集成测试打印编辑后的条目，`end_time` 从 `''` 变成了 `'10:00'`。
- **根因**：编辑表单里时间控件必须有默认值（`st.time_input` 不支持空），我用了固定的兜底值 10:00，保存时**无条件写回**——于是"用户没填的字段"被凭空造了出来。
- **修复**：原本为空、且控件值仍等于兜底默认值时，继续保持为空（`no_time_default` 参数区分"编辑已有任务"和"新建任务"）。
- **验证**：断言"空的结束时间未被捏造""原有开始时间保留""日期未被改动"。
- **衍生**：这次重构还引出一个回归——新建任务的"不指定具体时间"因为空任务没有时间而被**默认勾上**，导致用户选好的时间被丢弃；测试里"新课程落在第 7-8 节行"失败暴露了它，用独立的 `no_time_default=False` 修掉。

### 问题 5：WakeUp 导出的 .ics 把"双周课"拆成了 6 条

- **现象**：导入自己的课程表后，`应用光学实验` 这门双周课变成了 **6 条独立任务**（10-06、10-20、11-03…），日程管理列表被撑爆。
- **定位**：读自己的 `.ics` 源文件发现，导出的 6 个 `VEVENT` 虽然都写 `RRULE:FREQ=WEEKLY`，但每条的 `UNTIL` 只覆盖当次（例如 `DTSTART 10-06` 配 `UNTIL 10-12`）——**每次课被导出成一个"只重复一次"的事件**。
- **修复**：解析时按「课程名 + 时间 + 地点」把散落的事件**归并**，再把它们出现的周次排序，推断出规律：周次连续 → "每周"；周次全是同奇偶且间隔 2 → "单周/双周"。于是 6 条事件被正确还原成 **1 门"第 6-16 周双周"的课**。
- **验证**：断言 `应用光学实验` 只有 1 条、`week_parity=even`、`week_start=6`、`week_end=16`。

### 问题 6：ICS 里藏着的第二条 DESCRIPTION，把课程信息覆盖了

- **现象**：导入成功、课程和时间都对，但**节次全是空的**（"第 7-9 节"没解析出来），导致课程落不到正确的课表行。
- **定位**：`DESCRIPTION` 解析函数单独拿出来测是好的，于是打印事件对象，发现 `description` 是 `电子工艺实训@致腾楼316B` ——那是**闹钟提醒**的文案，不是课程描述。
- **根因**：ICS 的每个 `VEVENT` 里还嵌着 `VALARM` 子组件，**它里面也有一条 `DESCRIPTION`**；我的解析器没有区分嵌套层级，后出现的把先出现的覆盖了。
- **修复**：解析时维护组件嵌套深度，只取 `VEVENT` 第一层的属性。
- **验证**：断言每门课都有非空节次（16/16）。

### 问题 7：时区——UTC 的 UNTIL 和本地时间比，少算一周课

- **现象**：`电子工艺实训` 的结束周算出来比预期早一周。
- **定位**：对照源文件：`DTSTART;TZID=Asia/Shanghai:20260901T083000`（本地时间，08:30）与 `RRULE:...UNTIL=20270104T160000Z`（**UTC**，`16:00Z` = 北京时间次日 00:00）。
- **根因**：所有时间都当本地时间处理 → UNTIL 被当成"1 月 4 日 16:00 本地"，于是 12 月 29 日之后的课被误判为超出范围。
- **修复**：从 `VTIMEZONE` 读 `TZOFFSETTO`，只对带 `Z` 的值做 UTC→本地换算。
- **验证**：断言该课程为第 1-18 周（修复前是 17 周）。

### 问题 8：.bat 里写中文，cmd 报"不是内部或外部命令"

- **现象**：双击启动脚本，报一串莫名其妙的错误：
  ```
  '��先到' is not recognized as an internal or external command
  'ghua.edu.cn' is not recognized ...        ← URL 被从中间截断
  ```
- **定位**：`cmd.exe` 按**系统 OEM 代码页（中文 Windows 是 GBK）**解析批处理文件的**字节**，而我的文件是 UTF-8——一个中文 3 字节，会把命令行切碎，`echo` 前缀丢失、后半截被当成命令执行。
- **修复**：`.bat` **只放 ASCII**（含 `chcp 65001` 和 `PYTHONIOENCODING=utf-8` 两行环境设置），所有中文提示搬到 Python 启动器 `launcher.py`（Python 自己控制编码）。
- **后续**：改完仍报 `'Smart' is not recognized`。查文件字节发现是 **41 个 LF、0 个 CRLF** —— cmd 要求批处理用 CRLF 换行，纯 LF 会让 `REM` 行解析错乱。转成 CRLF 后零报错。

### 问题 9：Windows 上文件被占用，写盘偶发失败

- **现象**：测试里"加了 5 条，实际只进了 4 条"，且没有任何报错——`add_task` 静默返回了 `False`。
- **定位**：在测试里给 5 次 `add_task` 的返回值加断言，立刻定位到是哪一条失败；再打开日志看到 `替换数据文件失败`。
- **根因**：Windows 上 Defender / 文件索引 / 编辑器会**短暂占用**文件，`os.replace`（原子替换）偶发失败。我原来只尝试一次就放弃。
- **修复**：写入改成"临时文件 + 带线性退避的重试替换"（5 次），偶发占用能自愈；同样的重试也用在设置文件上。
- **验证**：断言 5 条全部写入成功，并且此后再未复现。（这个坑还以 `ReplaceFileW EIO` 的形式咬了编辑器一次，是真实环境问题而不是测试噪音。）

### 问题 10：手机上 13×8 的课表根本没法看

- **现象**：手机浏览器打开后，课表挤压成一条条看不清的窄柱。
- **定位**：这不是 bug 而是设计问题——桌面的"13 行 × 8 列"表格在 400px 宽的屏幕上必然失败。
- **修复**：两手准备——① 窄屏媒体查询（缩小字号/内边距）+ 表格外层加**横向滑动**容器；② 新增 **「📱 今日」列表视图**：今天几节课、几点、在哪、上完没有，一屏读完，这才是手机上真正好用的形态。
- **验证**：断言窄屏媒体查询已注入、表格有横滑容器、今日视图不渲染表格、已过课程淡显标"已结束"。

### 问题 11：校准出的作息和默认作息重叠，课程落错行

- **现象**：三节连堂的 `应用光学实验`（14:15 开始）被算成占第 5-9 节，而不是第 7-9 节。
- **根因**：从课表校准出"第 7 节 = 14:15 开始"后，**默认作息里"第 5 节 = 14:00-14:45"仍然包含 14:15**；按"第一个命中的行"取，就取到了第 5 节。
- **修复**：改为按"最贴近"匹配——判断开始取**开始时间最接近**的课，判断结束取**结束时间最接近**的课。
- **验证**：跨度断言 `(7, 9)`、`(3, 5)`、`(3, 4)` 全部正确。

### 问题 12：撞课时每张卡都撑满整格，卡片错位、下面还露出"空闲"

- **现象**：把子任务排到已经有的课上（12:00-13:30 的子任务碰上 10:15-12:25 的课），
  卡片不在它自己那一节上，而且它盖住的那一行背景里还印着"空闲"两个字。
- **定位**：先用 `AppTest` 把真正渲染出来的表格 HTML 打出来，逐格统计，发现
  "同一格里既出现卡片又出现`空闲`"的次数是 0——说明字面上没冲突；
  真正的问题是那一格**同时挂了两张卡片**：`应用光学`（第 3-5 节）和子任务（第 5 节）。
- **根因**：合并单元格（`rowspan`）里渲染多张卡片时，我给**每一张**都加了"撑满整格"
  的样式（`height:100%`）。两张卡就是 200% 高，必然溢出到下面那一行，
  而那一行恰好是没课的「空闲」格——于是既是"卡片错位"，又是"空闲没去掉"，
  两个现象其实是同一个 bug。
- **修复**：格子里只有一条日程时保持原样（连堂课仍然是一整块，中间无缝）；
  有两条以上时改成**并排成几列**，每列内部用 `flex-grow = 这条日程占的节次行数`
  精确占位，并用 `height: calc(100% + 2px)` 把单元格的内边距/边框误差补回来，
  让卡片边界和左侧节次行对齐；撞课的两张卡都加 `⚠ 撞课` 角标。
- **验证**：真实数据整表断言——子任务那一列必须是"前面空 2 行 + 自己占 1 行"、
  全表不存在"同一格既有卡片又有`空闲`"、每列的行数之和等于整格行数；
  再把修复前后 **14 个连堂格逐字节比对**，只有受影响的那 1 格变化；
  真实 `data/*.json` 的 SHA256 前后一致（测试全程只读真实数据，跑在工作区副本上）。

### 问题 13：课表里显示的"第6节"，其实是别的学校的默认作息

- **现象**：课表左侧出现一行"第6节 14:55-15:40"，夹在第 5 节（11:45）和真实的第 7 节（14:15）之间——
  时间不按顺序，而且这一行 7 个格子全都是"空闲"。
- **定位**：先把真正渲染出来的表格 HTML 打出来逐行统计，发现那一行 **7 格全写着"空闲"**，
  说明它根本没被任何课占用；再去读 `period_time_range()`：**没被校准到的节次会返回
  `config.py` 里写死的默认作息**（第 6 节 = 14:55-15:40）。
- **根因**：默认作息是给"还没导入课表"的情况兜底的；一旦导入了课表，说明我的真实作息已经被校准出来了，
  这时还把默认值当成"我的第 6 节"来显示，等于**把别的学校的作息当成了我的**。
  回头核对 `.ics` 原文：整份课表只用到第 1-2、3-4、3-5、7-8、7-9、9-10、11-12、11-13 节，
  **从来没有出现过第 6 节**——这个节次确实不在我的课表里。
- **修复**：把"左右紧邻两节之间、恰好缺一节"的空档认定为这一节的时间：中午那段（12:25-14:15）显示成
  **午休**。它是空档、不是课，所以占位字写"午休"而不是"空闲"，也不计进"空闲 N 节"；
  同时让这段空档**真的能接住任务**——12:30-13:30 的子任务会直接排进午休那一行。
  算不准就不猜：完全没校准、连着缺好几节、缺表头/表尾，都按原来的默认作息走。
- **验证**：纯函数断言（空档认定、行名、时刻匹配）+ 整表断言（左侧显示"午休 12:25/14:15"、
  假的"第6节"和"14:55"彻底消失、空着的午休格子写"午休"、不存在"同一格既有卡片又有空闲"）+
  保守性断言（不该认成午休的都不认）；子任务按"它自己的时间该占哪几行"核对；
  真实 `data/*.json` 的 SHA256 前后一致。

### 问题 14：一天几节课被写死成 13，别人课表里的第 14 节没地方放

- **现象**：被问到"我们学校一天 14 节课，只是我这学期没有第 14 节——那有第 14 节的人导入课表，能正常显示吗？"
  实测答案是**不能**：他的课会被塞进"其他时段"，或者只占第 13 节那一行。
- **定位**：造一份含"第13 - 14节 21:00-22:30"的 `.ics`，走完整导入链路并逐步打印：
  节次**解析是对的**（`periods = "13-14"`），但
  ① `_calibrate_periods()` 只迭代 `config.CLASS_PERIODS`（写死 13 节）→ 第 14 节的上下课时间**永远学不到**；
  ② `row_index_of_period(14)` 返回 `None` → 课表只有 13 行，"第13-14节"的课被截成 1 行，
  整条都在第 14 节的课直接掉进"其他时段"。
- **根因**：行集合被写死成"默认作息的 13 节"。可学校的节次数并不统一（13 节、14 节都有），
  **既然课表已经导入了，行就该由数据决定**，而不是由我预先假设的那个数字决定。
- **修复**：行集合改为 `默认作息的节次 ∪ 校准到的节次 ∪ 任务里写过的节次`（`config.period_numbers()`）；
  校准函数也改成按"事件里真正出现过的节次"存时间。于是别人导入带第 14 节的课表，
  第 14 节那一行会带着**它自己的时间**出现，课正常占两行（第 13-14 节连堂）。
- **改完还踩了一个坑**：第一版第 14 节仍然不出现——因为 `_week_table_html()` 的参数叫 `rows`，
  而函数开头又写了 `rows = []`，**参数被同名局部变量遮蔽**，`rows if rows else 默认行`
  读到的一直是那个空列表、静默退回 13 行。把局部变量改名成 `display_rows` 才正常。
  教训：参数和内部变量重名时，`if 参数 else 默认值` 会悄悄走默认分支 —— 所以断言必须打到"渲染结果"上，
  不能只断言函数返回值（我的纯函数断言当时全是 PASS）。
- **验证**：A 节次集合（含边界：不传 rows 时第 14 节仍不在默认表里）；
  B 完整 ICS→解析→校准链路（第 14 节时间学到 `21:45-22:30`）；
  C 真渲染（左侧出现"第14节"且带时间、卡片跨 2 行、"空闲 N 节"的分母跟着变成 14 节）；
  D 回归（只有 13 节的数据，整张表**逐字节一致**，含午休行）；
  E 真实 `data/*.json` 的 SHA256 前后不变。

### 问题 15：缺口分析第一版差点按"写死的 13 节"算

- **现象**：给「本周还排得下吗」写第一版时，我让 planner 用 `config.PERIOD_ROWS[index]` 把行下标换回节次。
- **根因**：课表的行列表是**动态**的（问题 14：导入的课表有第 14 节就多一行），
  而 `config.PERIOD_ROWS` 只是默认的 13 行 —— 一旦行列表长到 14 行，下标就会错位，空档时长全算错。
  更糟的是它不会报错，只会给出一个看似合理的数字。
- **修复**：planner 不碰行列表，改成由调用方传「每节多少分钟」（`{行下标: 分钟}`）；
  planner 只做求和与判断，保持纯函数、可单测。口径上仍然由周视图那一套规则算出占用，不重复实现。
- **验证**：`tests/test_planner.py` 里 `row_minutes` 用校准作息算（45/35 分钟）、
  被占用行从空档里扣掉、非法区间返回 0（不计入空档）。

### 问题 16：AI 拆解如果不缓存，每重跑一次就多烧一次 API

- **现象**：拆解面板第一版在渲染时直接调 `decompose_task()`。
  但 Streamlit 的交互会不断重跑整个脚本 —— 改一个日期、勾一个复选框都会重新调用一次 AI。
- **根因**：把「一次性请求」放在了「每帧都会执行的渲染路径」里。
- **修复**：结果存进 `session_state`（`SS_DECOMPOSE_ITEMS`），只有点 🤖 的那一次才请求；
  之后所有编辑都在本地数据上进行。顺带得到一个更好的性质：**确认之前一个字节都不落盘** ——
  AI 拆得不好，取消就是纯取消，不会有半成品混进日程。
- **验证**：`tests/test_decompose.py` 用 monkeypatch 顶掉 AI（不联网、不花钱）：
  点 🤖 → 面板出现「AI 拆出 3 步」→ 点「全部加入」→ 三条子任务带 `parent_id` 与耗时落盘；
  另一个用例点「取消」→ 数据条数不变。

### 问题 17：Dockerfile 漏拷一个模块，镜像照常启动、功能静默失效

- **现象**：Dockerfile 是逐个 `COPY` 文件的（为了"镜像里有什么一眼能看见"）。
  我新加的 `planner.py` 一开始没进 COPY 列表。
- **根因**：`ui_components.py` 里对 planner 的 import 有容错（`try/except ImportError`，
  这是为了让模块在缺 streamlit 时也能被 import）。于是漏拷时**容器照样起来、页面也不报错**，
  只有「🕳️本周空档 / 🧾本周要做 / ≈耗时」整块消失 —— 恰恰是最容易被评审当场问住的那种失效。
- **修复**：把 `planner.py` 加进 COPY 列表；并加一条自检规则：
  **项目里每个模块都必须出现在 Dockerfile 的 COPY 里**，漏了就报错。
- **验证**：部署自检脚本 53 项全过（含这条规则 + `tomllib` 真解析 config.toml +
  对正在运行的本机 Streamlit 打 `/_stcore/health` 实测返回 `ok`）。

### 问题 18：把 headless 设成 true，本地双击启动后浏览器不再自动打开

- **现象**：给部署写配置文件后，本地双击 `启动.bat`，服务其实已经起来了（端口在监听、页面能访问），
  但**浏览器不再自动弹出** —— 用户看到的现象就是"应用打不开了"。
- **根因**：`.streamlit/config.toml` 里我按部署需要写了 `headless = true`。
  而 `launcher.py` 一直是**靠 Streamlit 的默认行为**自动打开浏览器的（`headless = false` 时才会），
  它自己并没有开浏览器的代码 —— 于是配置一改，本地这条主路径就静默失灵了。
  部署子代理当时在交付说明里断言"本地界面没有任何变化"，这句是错的：
  **它只验证了配置文件能被解析，没有验证"本地启动这条路径"的用户可见行为**。
- **修复**：
  1. 配置里 `headless = false`（回到默认体验）；容器/云端由 Dockerfile 的
     `--server.headless=true` 显式覆盖，两边互不影响；
  2. `launcher.py` 现在**自己**在后台线程里 `webbrowser.open(...)`，
     配置文件怎么写都不再影响本地启动 —— 双保险。
- **教训**：改共享配置时要问"谁依赖了这个默认值"。凡是被"顺手改好"的默认值，
  都要回到**使用它的那条路径**上验一遍，而不是只验证文件合法。
- **验证**：`tomllib` 解析后 `server.headless is False`；诊断实例
  （`streamlit run main.py --server.port=8599`）启动成功并打印 URL；
  `tests/` 49 项全过。

### 问题 19：多用户第一版，每个新访客都会看到机主的真实课表（隐私级）

- **现象**：改完多用户后跑测试，删掉一个空间、应用发了新的空空间，结果新空间里**立刻出现了机主那 19 条真实课表**。
- **根因**：启动流程对**每个**空间都调了一次「把旧 `data/schedules.json` 迁进来」。
  单机自用时这是对的（把老数据搬进新存储），但多用户模式下等于**把机主的私人课表复制给每一个陌生人**。
  这个 bug 不是读代码看出来的，是"删空间后新空间应该为空"这条断言逼出来的。
- **修复**：迁移只对**默认空间**（`local`，也就是机主自己）生效；非默认空间一律拒绝并返回原因。
  新增断言：新空间迁移前后条数都是 0。
- **教训**：把"本地/单机"的便利行为复制到"多人共享"的场景里，便利就会变成泄露。

### 问题 20：`with sqlite3.connect(...) as conn` 并不会关闭连接

- **现象**：测试里"删掉数据库重建"报 `PermissionError: [WinError 32] 另一个程序正在使用此文件`。
- **根因**：我当时以为 `with sqlite3.connect(...) as conn` 是"打开-用完关闭"。它其实**只管理事务**
  （正常提交、异常回滚），**连接不会关闭**。于是每次读写都漏一个连接，Windows 上 sqlite 文件一直被占用。
- **修复**：写了一个 `_cursor()` 上下文管理器：`with conn:` 管事务、`finally: conn.close()` 管连接，
  所有读写统一走它。
- **教训**：标准库里"看起来像 with-open"的写法不一定是 with-open。连接、文件、锁这类资源要显式确认。

### 问题 21：Dockerfile 漏拷 `storage.py`，容器起不来

- **现象**：多用户版新增了 `storage.py`，但 Dockerfile 是逐个 `COPY` 文件的（为了"镜像里有什么一眼可见"），
  新模块没加进去 → 镜像能构建成功，容器**一启动就崩**（`task_manager` 里 `import storage` 失败）。
- **根因**：和问题 17 是同一个坑（那次漏的是 `planner.py`，那次更阴——失败被容错吞掉、只是功能静默消失）。
- **修复**：把 `storage.py` 加进 COPY 列表；并把**「项目里每个 `.py` 模块都必须出现在 Dockerfile 的 COPY 里」**
  写成一条真测试（`tests/test_deploy_assets.py::test_dockerfile_copies_every_module`），漏了就红。
- **教训**：手工维护的清单必须有测试兜底。第一次踩是意外，第二次踩就是没吸取教训。

## 五、验证方式（我如何确认"它真的能用"）

评审要求"能独立运行、修改、解释作品"，所以我刻意**不靠"看一眼觉得对"**，而是搭了三层验证：

| 层次 | 手段 | 规模 |
|---|---|---|
| 逻辑层 | 纯函数单元断言（周次、跨度、类型映射、解析容错…） | 数十项 |
| 界面层 | `streamlit.testing.v1.AppTest`——**在真实 Streamlit 运行时里执行 main.py**，模拟点击按钮、填表单、翻周、导入文件，断言页面元素与落盘结果 | 近百项 |
| 端到端 | 用**自己的真实课表 `.ics`** 走完整链路：上传 → 解析 → 预览 → 确认 → 落盘 → 渲染 → 编辑 → 删除；并用**真实 DeepSeek API** 验证自然语言链路 | 每轮回归 |

几条具体做法：
- **测试数据与真实数据隔离**：跑测试前把 `data/*.json` 备份到临时目录，测试用独立数据，跑完恢复，并用 **SHA256 逐字节比对**确认用户数据没被动过。
- **真启动验证**：每轮都实际 `streamlit run main.py`，用 HTTP 请求确认 `/_stcore/health` 返回 200，而不是只看测试通过。
- **失败就复现**：任何一次"偶发失败"都要先让它可复现（比如给 5 次写入加断言），再定位根因。
- **可以自己复跑**：整理后的验证都在 `tests/`，标准库直接跑，零新依赖：

  ```bash
  python -m unittest discover -s tests -t .
  ```

  覆盖「预计耗时 → 缺口分析」「AI 拆解 → 带 parent_id 落盘 → 级联删除」「午休空档与节次数不写死」
  以及渲染层的不变量（同一格不会同时出现卡片和"空闲"、并排列的行数之和必须等于 rowspan）。
  测试会把真实 `data/*.json` **只读复制**到隔离目录再改 `DATA_FILE` 指向它，
  所以跑测试永远不会动到你的日程；`tests/_support.py` 里还能随时复核真实文件的 SHA256。

## 六、如何运行

### 环境要求
- Windows（也支持 macOS/Linux，启动方式见下）
- Python 3.10 以上（开发环境 3.14.0）
- 一个 DeepSeek API Key（**可选**：不配也能用手动输入、课表导入、周视图等全部非 AI 功能）

### 一键启动（Windows）
```
双击  启动.bat
```
它会自动：找 Python → 检查依赖（缺了自动装，先走清华镜像、失败换官方源）→ 生成 `.env` → 选一个没被占用的端口 → 启动并打印访问地址。

### 手动启动（任意系统）
```bash
cd smart-scheduler
pip install -r requirements.txt
streamlit run main.py
```

### 配置 AI（可选）

默认走**智谱 GLM 的免费档**（`glm-4.7-flash`，输入与输出都不收费）：
```bash
cp .env.example .env      # Windows: copy .env.example .env
# 编辑 .env，把 ZHIPU_API_KEY 的值换成你自己的 Key（open.bigmodel.cn 免费注册即可）
```

想继续用 DeepSeek（按量计费）也**不用改代码**：把 `DEEPSEEK_API_KEY` 填上就行。
程序会自动挑「已经配了 Key 的那一家」——这样"手上只有哪家的 Key 就用哪家"，
不会出现"填了 Key 却提示未配置"。两家都配了时，用谁由 `LLM_PROVIDER` 决定。
换模型同样不用改代码：`LLM_MODEL=glm-4.5-flash` 写一行即可。

不配置时，界面会提示"未配置AI服务，当前仅支持手动输入模式"，其余功能不受影响。

### 手机访问
手机连**同一个 WiFi**，浏览器打开应用侧边栏「📱 手机上使用」里显示的地址即可（可在浏览器菜单里"添加到主屏幕"）。

## 六、多用户版：怎么让同学也能用

> 这一节是 2026-09 之后新增的能力。单机自用（双击 `启动.bat`）的用法**完全没变**。

### 6.1 一个空间码，就是一份独立的日程

- 打开应用时，程序会给你一个**空间码**（形如 `kQ3fZ_a91Bx`），并写进 URL（`?u=...`）；
- 任务和设置都按空间码隔离（存在 `data/app.db`，标准库 SQLite）——**同学各自有自己的码，互相看不到**；
- 换手机 / 换浏览器：打开**带同一个码的链接**就接着用；点「添加到主屏幕」后链接会一直保留；
- 面板里还有：二维码（给另一台设备扫）、导出我的数据（JSON）、两步确认删除整个空间。

⚠️ **空间码就是唯一凭证，没有密码**：谁拿到链接谁就能看到那份日程。界面上已经写明"别放敏感信息"。
想要真账号（注册/登录/改密），升级点在 `storage.py` 的身份层，不影响其它代码。

### 6.2 单机 vs 多用户，程序怎么知道？

| 场景 | 是否设 `SS_MULTIUSER` | 行为 |
|---|---|---|
| 自己电脑上双击启动 | 不设 | 没带 `?u=` 就用默认空间 `local`，旧的 `data/schedules.json` 自动迁进来 —— **体验和以前一模一样** |
| 部署到服务器 | 设 `SS_MULTIUSER=1` | 没带 `?u=` 的访客**自动领一个新空间码**（空空间），不会和别人串数据 |

### 6.3 部署到云服务器

见 **[`deploy/部署指南-多用户.md`](deploy/部署指南-多用户.md)**（Docker + Caddy 自动 HTTPS + 持久卷 + 备份 + 排查表）。

**一条必须知道的现实**：免费的 Streamlit Community Cloud **文件系统会重置** ——
重新部署或实例休眠后，所有人记的日程会一起没。多用户要真正可用，
必须放在**有持久磁盘**的地方（自己的云服务器 / 家里的电脑 + 内网穿透）。

### 6.4 手机当 App 用

手机浏览器打开 → 菜单 →「添加到主屏幕」→ 以后点图标直接进（独立图标、全屏、无地址栏）。
`deploy/` 里备好了 PWA 三件套（`manifest.webmanifest` + `sw.js` + 两个尺寸的图标）。
service worker **刻意不缓存 `/app`**：应用数据在服务器上且是多人共享的，缓存它只会看到过期日程。

## 九、关于 AI 的使用（按要求说明）

**AI 做了什么**：本项目按招新要求借助 AI Agent 完成。具体包括——需求梳理与方案讨论、代码骨架与实现、写自动化测试、以及在真实运行中排查上面第 4 节列出的那些问题。AI 也参与到"怎么做更好"的讨论中（例如"节次 vs 上下午""AI 结果要不要人工确认""已结课要不要写进数据"这几个关键取舍）。

**我自己做了什么、能解释什么**：
- 需求与场景来自我自己的真实使用（第 1 节的工具对比是我实际用下来的结论）；
- 每个功能我都能对着代码讲清楚实现路径，并用真实数据跑通；
- 第 4 节的每个问题，我都能复述"现象—根因—修复—如何验证"，并能独立复现；
- 修改能力：我曾自己改过作息表（`config.py` 的 `CLASS_PERIODS`）、学期设置、以及测试数据来验证边界情况。

**为什么不直接交 AI 生成的成品**：因为评审要的是"能独立运行、修改、解释"。这个项目里最有价值的部分恰恰不是代码量，而是**第 4 节那 21 个真实问题**——它们都是跑起来、拿真实课表试、写测试断言之后才暴露的，这部分无法由 AI 一次性生成。
